# 서비스 계획

1단계 구현 전에 정한 서비스 규칙이다. 작업 묶음을 설계할 때 출발점으로 쓴다. 구현한 뒤에는 코드와 테스트가 기준이며, 이 문서는 갱신하지 않는다.

## 약관 동의
- 회원가입에서 이용약관과 개인정보 수집·이용(필수), 마케팅 수신(선택) 동의를 받고, 결제 직전에 취소·환불 규정 동의를 받는다.
- 약관은 버전별로 저장하고, 누가 언제 어느 버전에 동의했는지 기록한다.
- 필수 약관이 개정되면 다음 로그인 때 다시 동의받는다.
- 본문은 시드로 넣고 어드민 편집 화면은 만들지 않는다. 가상 서비스의 예시 문구임을 표시한다.

## 인증과 역할
- 역할은 사용자와 운영자 둘이다. 운영자 계정은 시드로 만들고, 공개 가입 경로와 권한 세분화는 두지 않는다.
- 어드민은 이메일 로그인만 받는다. 주문과 회원은 조회만 하며, 대리 취소와 회원 정지는 넣지 않는다.
- 이메일 가입은 인증을 마쳐야 예매할 수 있다. 제공자가 검증한 소셜 이메일은 인증을 생략하고, 직접 입력받은 이메일은 인증한다.
- 소셜 로그인은 구글과 카카오를 지원한다. 같은 이메일의 기존 계정에 자동으로 연결하지 않고, 기존 방식으로 로그인한 뒤 내 정보에서 연결한다.
- 첫 소셜 로그인은 약관 동의를 거쳐야 가입이 끝난다. 제공자가 이메일을 주지 않으면 직접 입력받는다.
- 소셜 전용 계정에는 비밀번호 변경과 재설정 메뉴를 보여 주지 않는다.

## 회원 탈퇴
- 아직 열리지 않은 회차의 유효한 티켓이 있으면 탈퇴할 수 없다.
- 계정을 지우지 않고 이름, 이메일, 소셜 연결 정보를 지우며, 로그인 세션을 즉시 끊는다.
- 주문과 결제 기록은 익명 상태로 보존한다. 실제 보존 기간에 맞춘 삭제는 구현하지 않는다.
- 리뷰는 작성자를 "탈퇴한 사용자"로 표시하고 내용과 별점을 유지한다.
- 남은 포인트는 사라진다. 같은 이메일로 다시 가입할 수 있고, 이전 기록은 이어지지 않는다.

## 공연과 가격
- 좌석 등급과 가격은 공연별로 정하고, 등급은 구역 단위로 지정한다. 회차별 가격 차이는 두지 않는다.
- 회차 좌석은 회차를 등록할 때 공연장의 좌석 수만큼 만든다.
- 주문에는 주문 시점의 가격을 저장한다.
- 공연장은 시드로만 만들고 좌석 배치 편집기는 만들지 않는다.
- 회차 취소는 시드에 상태값만 두고, 어드민 기능은 8단계에서 다룬다.

## 공연 목록
- 검색은 공연 제목 부분 일치만 지원하고, 전문 검색 엔진은 쓰지 않는다.
- 필터는 고정된 장르 목록과 판매 상태, 정렬은 공연 시작일, 최근 등록, 별점 순이다. 인기순은 넣지 않는다.
- 페이지는 오프셋 방식으로 시작한다.

## 주문 취소
- 회차 시작 24시간 전까지 수수료 없이 전액 환불한다. 환불 금액은 실제 결제 금액이다.
- 취소된 회차 좌석은 바로 다시 판매하고, 매진이던 회차는 판매 중으로 돌아간다.
- 취소된 티켓은 무효가 되지만 기록은 남긴다.
- 환불에 실패하면 주문 상태를 바꾸지 않고 오류를 보여 준다. 실패 복구는 8단계에서 다룬다.

## 리뷰
- 회차가 끝났고 유효한 티켓이 있는 사용자만 쓸 수 있다. 취소된 주문이나 취소된 회차의 티켓으로는 쓸 수 없다.
- 사용자당 공연별 1개이며, 같은 공연을 다시 봤다면 기존 리뷰를 수정한다.
- 별점 1~5(정수)와 본문은 필수이고, 사진은 받지 않는다. 관람 전 기대평과 신고 기능은 넣지 않는다.
- 작성자는 수정과 삭제를 할 수 있고, 운영자는 숨김만 할 수 있다.
- 평균 별점은 조회할 때 계산하고, 9단계에서 측정한 뒤 개선을 판단한다.

## FAQ와 공지사항
- DB에 저장하고 어드민에서 등록, 수정, 삭제, 노출 여부, 표시 순서를 관리한다.
- 스토어에서는 비로그인 공개 화면으로 서버 렌더링한다.
- FAQ는 고정된 분류(예매, 결제·환불, 계정 등)로 필터링하고, 검색은 넣지 않는다.

## 쿠폰
- 할인은 정액 또는 정률이며, 정률에는 최대 할인액을 둘 수 있다.
- 유효 기간과 최소 주문 금액을 두고, 선택적으로 특정 공연에만 쓰게 한다.
- 어드민에서 쿠폰을 만들고, 사용자가 쿠폰 화면에서 직접 받는다. 수량 제한을 둘 수 있고, 쿠폰 하나당 1장만 받을 수 있다.
- 주문당 1장만 쓸 수 있다. 코드 입력 방식은 넣지 않는다.
- 주문을 취소하면 유효 기간이 남은 쿠폰만 돌려준다.

## 포인트
- 잔액만 저장하지 않고 적립, 사용, 복구를 포인트 원장에 모두 기록한다.
- 실제 결제 금액의 1%를 회차가 끝난 뒤 적립한다. 처음에는 단순한 주기 작업으로 처리한다.
- 1포인트는 1원이다. 쿠폰을 먼저 적용한 뒤 남은 금액에 포인트를 쓰고, 최소 결제 금액 1,000원을 남긴다.
- 주문을 취소하면 사용한 포인트를 돌려준다. 유효 기간과 리뷰 적립은 두지 않는다.

## 메일
- 가입 인증, 비밀번호 재설정, 예매 확인, 주문 취소 확인 메일을 보낸다.
- 1단계에서는 동기로 보내고, 7단계에서 문제를 확인한 뒤 큐로 옮긴다.
