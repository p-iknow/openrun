020 Drizzle 스키마 문법

Drizzle 스키마 파일(apps/api/src/db/schema/)에 쓰는 문법을 모은 참고 문서다. 문법마다 코드, drizzle-kit이 만드는 SQL, TS 타입에 주는 영향을 적는다. 처음부터 읽지 않고, 다른 문서에서 링크로 넘어와 필요한 절만 읽는다. 이 저장소가 왜 그 문법을 골랐는지는 각 문서에 있고, 여기에는 문법이 하는 일만 적는다. 기준 버전은 drizzle-orm 0.45다. SQL과 DB 개념은 019 문서에 있다.

pgTable

import { index, integer, pgTable, text } from 'drizzle-orm/pg-core';

export const shows = pgTable(
  'shows', // ① SQL 테이블 이름
  {
    // ② 컬럼: 키는 코드에서 쓰는 이름
    id: integer().primaryKey().generatedAlwaysAsIdentity(),
    title: text().notNull(),
  },
  (table) => [index().on(table.title)], // ③ 테이블 단위 설정(선택)
);
  • ① DB에 만들어지는 실제 테이블 이름이다.
  • ② 객체의 키 하나가 컬럼 하나다. 키는 코드에서 쓰는 이름이라, 쿼리에서는 shows.title, 결과 행에서는 row.title로 쓴다.
  • ③ 컬럼 하나에 붙일 수 없는 것(인덱스, 여러 컬럼에 걸친 제약)을 둔다. ②의 컬럼을 table로 받아 배열로 돌려준다. 없으면 생략한다.

pg-core는 PostgreSQL용 빌더 모음이다. MySQL은 mysql-core, SQLite는 sqlite-core를 쓴다. DB마다 지원하는 타입이 달라서 나뉘어 있다.

반환값 shows는 두 곳에 쓰인다. drizzle-kit은 이 값을 읽어 마이그레이션 SQL을 만들고, 앱은 db.select().from(shows)처럼 쿼리 재료로 쓴다(004 문서).

컬럼 빌더

빌더 함수 하나가 PostgreSQL 컬럼 타입 하나에 대응한다.

빌더 PostgreSQL 타입 TS 타입 담는 것
integer() integer number 정수. 약 ±21억까지
text() text string 길이 제한 없는 문자열
boolean() boolean boolean 참, 거짓
timestamp() timestamp 또는 timestamptz Date 일시(옵션)
pgEnum이 돌려준 함수 직접 만든 enum 타입 문자열 리터럴 유니언 정해진 값 중 하나(pgEnum)

빌더 뒤에 .notNull()처럼 점으로 이어 붙이는 메서드를 이 문서에서는 수식어라고 부른다. 수식어는 SQL의 제약이나 기본값이 되고, 동시에 TS 타입도 바꾼다.

선택 읽기: varchar(n) 대신 text를 쓰는 이유

PostgreSQL에서는 varchar(n)과 text의 저장 방식과 성능이 같다. varchar(50)은 길이 검사만 더한 text다. 길이 제한은 사용자에게 알맞은 오류 메시지를 줄 수 있는 API 검증에서 거는 편이 낫다.

컬럼 이름

title: text(),                  // 컬럼 이름: title
venueId: integer(),             // 컬럼 이름: "venueId"
venueId: integer('venue_id'),   // 컬럼 이름: venue_id

빌더의 첫 인자는 SQL 컬럼 이름이고, 생략할 수 있다. 생략하면 객체 키가 그대로 컬럼 이름이 된다. 키가 venueId처럼 대문자를 포함하면 컬럼도 "venueId"가 되는데, PostgreSQL은 따옴표 없는 이름을 소문자로 바꿔 읽으므로 SQL에서 매번 "venueId"처럼 따옴표를 쳐야 한다. 그래서 두 단어 이상이면 첫 인자로 'venue_id' 같은 snake_case 이름을 적는다.

코드에서는 여전히 키 이름(shows.venueId, row.venueId)을 쓴다. 키와 컬럼 이름을 잇는 일은 Drizzle이 한다.

선택 읽기: casing 옵션

drizzle(url, { casing: 'snake_case' })를 주면 키에서 snake_case 컬럼 이름을 자동으로 만든다. 같은 옵션을 drizzle-kit 설정(drizzle.config.ts의 casing)과 drizzle()을 부르는 모든 곳에 넣어야 한다. 한 곳이라도 빠지면 그곳만 다른 이름을 찾는다.

.notNull()

title: text().notNull(),
"title" text NOT NULL

컬럼을 비울 수 없게 한다(NOT NULL). 수식어가 없으면 NULL을 허용한다.

읽을 때(SELECT) 타입 넣을 때(INSERT)
text() string | null 선택. 빼면 NULL
text().notNull() string 필수 빼면 컴파일 오류

기본값이 있으면 INSERT에서 다시 선택이 된다(.default()).

.primaryKey()

id: integer().primaryKey(),
"id" integer PRIMARY KEY

컬럼을 기본 키로 만든다. 값이 겹칠 수 없고 비어 있을 수 없다(NOT NULL이 함께 따라온다). PostgreSQL은 기본 키에 인덱스를 자동으로 만든다.

컬럼 두 개를 묶어 기본 키로 삼으려면 pgTable의 세 번째 인자에 primaryKey({ columns: [table.a, table.b] })를 둔다.

.generatedAlwaysAsIdentity()

id: integer().primaryKey().generatedAlwaysAsIdentity(),
"id" integer PRIMARY KEY GENERATED ALWAYS AS IDENTITY (sequence name "shows_id_seq" INCREMENT BY 1 MINVALUE 1 ...)

행을 넣을 때 DB가 번호를 1, 2, 3… 자동으로 매긴다. 번호는 테이블마다 따로 있는 시퀀스가 기억한다. 예전에 쓰던 serial을 대신하는 표준 SQL 방식이다.

수식어 번호를 직접 넣으면 INSERT 타입
.generatedAlwaysAsIdentity() DB가 거부한다 키가 빠진다
.generatedByDefaultAsIdentity() 넣은 값을 쓴다. 시퀀스는 모르므로 나중에 같은 번호가 나와 충돌할 수 있다 선택

TRUNCATE 테이블 RESTART IDENTITY는 행을 모두 지우면서 시퀀스를 1로 되돌린다. 행만 지우면 다음 번호는 지우기 전 번호에서 이어진다.

.default()와 .defaultNow()

isCancelled: boolean('is_cancelled').notNull().default(false),
createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
"is_cancelled" boolean DEFAULT false NOT NULL
"created_at" timestamp with time zone DEFAULT now() NOT NULL

SQL의 DEFAULT를 붙인다. INSERT에서 값을 주지 않으면 DB가 이 값으로 채운다. 함수의 기본 매개변수(function f(x = false))와 비슷하다.

  • .default(값): 고정된 값을 기본값으로 둔다.
  • .defaultNow(): DEFAULT now()다. now()는 PostgreSQL의 "지금 시각" 함수라, Node 서버가 아니라 DB 서버의 시계를 읽는다.
읽을 때(SELECT) 타입 넣을 때(INSERT)
.notNull() boolean 필수
.notNull().default(false) boolean 선택 빼면 DB가 false로 채운다
선택 읽기: $defaultFn()은 다르다

.$defaultFn(() => crypto.randomUUID())처럼 쓰면 기본값을 DB가 아니라 Drizzle이 INSERT 직전에 Node에서 만든다. SQL에 DEFAULT가 생기지 않으므로, Drizzle을 거치지 않고 SQL로 직접 넣으면 기본값이 적용되지 않는다.

timestamp 옵션

startsAt: timestamp('starts_at', { withTimezone: true }),
startsAt: timestamp('starts_at', { withTimezone: true, mode: 'string' }),
옵션 값 뜻
withTimezone true 컬럼 타입이 timestamp with time zone(timestamptz)이 된다. 절대 시점으로 저장한다(019 문서)
false(기본값) 시간대 없는 timestamp가 된다. 받은 시각의 숫자만 저장한다
mode 'date'(기본값) TS에서 Date 객체로 읽고 쓴다
'string' TS에서 문자열로 읽고 쓴다. Drizzle이 Date로 바꾸지 않는다

mode: 'date'인 값을 JSON 응답에 담으려면 toISOString()으로 문자열로 바꾼다. JSON에는 Date 타입이 없다.

.references()

venueId: integer('venue_id')
  .notNull()
  .references(() => venues.id),
ALTER TABLE "shows" ADD CONSTRAINT "shows_venue_id_venues_id_fk"
  FOREIGN KEY ("venue_id") REFERENCES "public"."venues"("id")
  ON DELETE no action ON UPDATE no action;

컬럼에 외래 키 제약을 건다. SQL은 부분별로 이렇게 읽는다.

부분 뜻
ALTER TABLE "shows" shows 테이블의 모양을 바꾼다
ADD CONSTRAINT "shows_venue_id_venues_id_fk" 제약을 더한다. 따옴표 안은 drizzle-kit이 지은 제약 이름이고, 오류 메시지에 나온다
FOREIGN KEY ("venue_id") 이 테이블의 venue_id가 외래 키다
REFERENCES "public"."venues"("id") venues 테이블의 id를 가리킨다
ON DELETE no action 가리켜지는 행을 지울 때의 동작(아래)
ON UPDATE no action 가리켜지는 행의 id를 바꿀 때의 동작

인자가 화살표 함수인 이유

.references(venues.id)가 아니라 .references(() => venues.id)다. Drizzle은 함수를 저장만 해 두고, 참조 정보가 필요할 때(마이그레이션 생성, 쿼리 실행) 부른다. 두 스키마 파일이 서로를 import하면(순환 import), 한쪽 파일을 읽는 순간에는 다른 쪽 값이 아직 정의되지 않았을 수 있다. 함수로 미뤄 두면 모든 파일을 읽은 뒤에 부르므로 안전하다. React의 lazy(() => import(...))가 함수를 받는 것과 같은 이유다.

onDelete, onUpdate

.references(() => shows.id, { onDelete: 'cascade' })

두 번째 인자로 가리켜지는 행(부모)을 지우거나 id를 바꿀 때, 가리키는 행(자식)을 어떻게 할지 정한다. 주지 않으면 no action이다.

값 부모를 지우면
'no action'(기본값) 자식이 하나라도 남아 있으면 삭제가 실패한다
'restrict' no action과 거의 같다. 검사 시점만 다르다
'cascade' 자식도 함께 지운다
'set null' 자식의 외래 키 컬럼을 비운다. 컬럼이 NOT NULL이면 쓸 수 없다
'set default' 자식의 외래 키 컬럼을 기본값으로 바꾼다

PostgreSQL은 외래 키 컬럼에 인덱스를 자동으로 만들지 않는다. 그 컬럼으로 찾는 일이 있으면 index()를 따로 둔다.

index()

export const performances = pgTable(
  'performances',
  { /* ... */ showId: integer('show_id').notNull() },
  (table) => [index().on(table.showId)],
);
CREATE INDEX "performances_show_id_index" ON "performances" USING btree ("show_id");

pgTable의 세 번째 인자에서 인덱스를 만든다. SQL은 "performances의 show_id에 B-tree 방식으로 performances_show_id_index라는 인덱스를 만든다"이다.

쓰는 법 뜻
index().on(table.a) 이름은 drizzle-kit이 테이블_컬럼_index로 짓는다
index('my_idx').on(table.a) 이름을 직접 정한다
index().on(table.a, table.b) 여러 컬럼을 묶은 인덱스. 순서가 중요하다(a로 찾거나 a와 b로 함께 찾을 때 쓰인다)
uniqueIndex().on(table.a) 인덱스이면서 값이 겹치지 못하게 막는다

방식을 정하지 않으면 PostgreSQL 기본값인 B-tree다.

pgEnum

export const GENRES = ['musical', 'play', 'concert', 'classical_dance', 'kids_family'] as const;
export type Genre = (typeof GENRES)[number];
export const genre = pgEnum('genre', GENRES);

// 테이블 안에서
genre: genre().notNull(),
CREATE TYPE "public"."genre" AS ENUM('musical', 'play', 'concert', 'classical_dance', 'kids_family');
ALTER TABLE "shows" ADD COLUMN "genre" "genre" NOT NULL;
  1. as const 배열 타입이 string[]이 아니라 읽기 전용 튜플 readonly ['musical', 'play', ...]가 된다. 값 하나하나가 리터럴 타입으로 남는다.
  2. (typeof GENRES)[number] "튜플의 아무 칸"의 타입, 즉 'musical' | 'play' | 'concert' | 'classical_dance' | 'kids_family'다. 값 목록과 타입을 배열 하나에서 얻으므로 둘이 어긋나지 않는다.
  3. pgEnum('genre', GENRES) PostgreSQL에 genre라는 새 타입을 만든다(CREATE TYPE). 테이블에 딸린 것이 아니라 DB에 따로 있는 타입이라 여러 테이블에서 쓸 수 있다. 반환값은 이 타입의 컬럼을 만드는 빌더 함수다. 두 번째 인자는 비어 있지 않은 문자열 튜플이어야 한다.
  4. genre().notNull() enum 타입의 컬럼이다. 인자를 생략하면 다른 빌더처럼 키가 컬럼 이름이 된다. TS 타입이 위의 유니언이라 목록에 없는 값은 컴파일 오류가 나고, SQL로 직접 넣어도 DB가 거부한다.

SQL 둘째 줄의 첫 "genre"는 컬럼 이름, 두 번째 "genre"는 타입 이름이다.

값을 바꾸는 마이그레이션

바꾸는 것 SQL
값 더하기 쉬움 ALTER TYPE "genre" ADD VALUE 'opera'
값 이름 바꾸기 ALTER TYPE "genre" RENAME VALUE 'play' TO 'drama'. 저장된 행도 새 이름으로 보인다
값 빼기 어려움 지우는 명령이 없다. 그 값을 쓰는 행을 먼저 바꾸고, 새 타입을 만들어 컬럼을 옮긴 뒤 옛 타입을 지운다

$inferSelect와 $inferInsert

테이블 정의에서 행 타입을 꺼낸다. 수식어 규칙이 그대로 반영된다.

type ShowRow = typeof shows.$inferSelect; // 읽어 온 행
// { id: number; venueId: number; title: string; genre: Genre; createdAt: Date; ... }

type NewShow = typeof shows.$inferInsert; // 넣을 값
// { venueId: number; title: string; genre: Genre; createdAt?: Date; ... }
컬럼 정의 $inferSelect $inferInsert
수식어 없음 T | null 선택(T | null)
.notNull() T 필수
.notNull().default(...), .defaultNow() T 선택
.generatedAlwaysAsIdentity() number 없음

db.insert(shows).values(...)가 받는 값이 $inferInsert 모양이고, db.select().from(shows)의 결과 행이 $inferSelect 모양이다. 따로 이름을 붙이지 않아도 쿼리에서 추론된다.

relations()

import { relations } from 'drizzle-orm';

export const showsRelations = relations(shows, ({ many }) => ({
  performances: many(performances),
}));

// drizzle(url, { schema: { shows, performances, showsRelations, ... } })로 넘기면
db.query.shows.findMany({ with: { performances: true } });
// → [{ id: 1, title: '...', performances: [{ id: 1, ... }, ...] }, ...]

관계를 선언해 두면 db.query로 중첩 객체를 한 번에 조회할 수 있다(Relational Queries). GraphQL처럼 "공연과 그 회차들"을 중첩해서 받는다.

.references() relations()
무엇인가 DB의 외래 키 제약 Drizzle 쿼리 편의 기능
누가 아는가 PostgreSQL Drizzle(TypeScript 코드)만
마이그레이션에 나오는가 나온다 나오지 않는다

0.45의 relations()는 모든 테이블과 관계를 한 객체로 모아 drizzle()에 넘겨야 한다. v1의 defineRelations도 같다. 이 저장소는 쓰지 않는다(이유는 021 문서).
