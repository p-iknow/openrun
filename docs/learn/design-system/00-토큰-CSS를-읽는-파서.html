토큰 CSS를 읽는 파서: read-tokens.ts의 원리

Storybook 토큰 화면은 packages/store-ui/src/docs/read-tokens.ts가 tokens.css를 글자 그대로 읽어 만든 데이터로 그린다. 이 파서가 왜 필요한지, 문자열 찾기와 정규식으로 어떻게 "의미 토큰 → 팔레트 → 값" 연결을 뽑는지, 어떤 가정에 기대는지 정리한다.

한눈에 보기

read-tokens.ts는 진짜 CSS 파서가 아니라 문자열 찾기와 정규식으로 만든 작은 파서다. tokens.css에서 :root(기본 팔레트)와 @theme(의미 토큰) 블록을 잘라 --이름: 값; 선언을 뽑고, var(--blue-500) 같은 값을 팔레트 사전에서 찾아 hex로 바꾼다.

왜 CSS 원문을 읽나

토큰 화면에는 "의미 토큰 primary는 팔레트 blue-500에 연결되고, 값은 #3182f6이다" 같은 표가 나와야 한다. 이 표를 만드는 방법을 셋 비교했다.

방법 결과
스토리에 표를 직접 적기 어긋남 tokens.css를 고칠 때 스토리도 고쳐야 한다. 깜빡하면 문서가 틀린 값을 보여 준다.
브라우저에서 getComputedStyle로 읽기 정보 부족 var(--blue-500)가 이미 #3182f6으로 풀린 값만 나온다. 어느 팔레트에 연결됐는지는 알 수 없다.
CSS 원문을 읽어 파싱하기 선택 --color-primary: var(--blue-500);라는 글자에서 연결 관계를 직접 뽑는다. 값의 출처는 tokens.css 하나뿐이다.

?raw로 파일을 문자열로 받기

Vite에서 import 경로 끝에 ?raw를 붙이면 파일을 스타일이나 모듈로 처리하지 않고 내용 전체를 문자열 하나로 넘겨 준다. Storybook은 Vite로 돌므로 스토리에서 바로 쓸 수 있다. 

// packages/store-ui/src/docs/tokens.stories.tsx
import tokensCss from '../tokens.css?raw'; // ':root {\n  --grey-50: #f9fafb; ...' 같은 문자열
import { readTokens } from './read-tokens.js';

const tokens = readTokens(tokensCss);

?raw import의 타입은 tsconfig.json의 "types": ["vite/client"]가 알려 준다. dist를 만드는 tsconfig.build.json은 src/docs와 스토리, 테스트를 빼므로 이 파서는 패키지 결과물에 들어가지 않는다.

입력: tokens.css의 두 블록

파서가 보는 곳은 두 블록뿐이다. 나머지 주석과 @theme inline 블록은 무시한다.

:root {                              /* ① 기본 팔레트 */
  --grey-50: #f9fafb;
  --blue-500: #3182f6;
  /* ... */
}

@theme {                             /* ② 의미 토큰 */
  --color-*: initial;
  --color-primary: var(--blue-500);
  --color-surface: #ffffff;
  --text-caption: 0.75rem;
  --text-caption--line-height: 1.5;
  --spacing-lg: 1rem;
  --radius-card: 12px;
  /* ... */
}

getTopLevelBlock: 블록 잘라 내기

/**
 * `selector` 블록의 최상위 내용만 돌려준다. 중괄호 깊이를 세어 짝이 맞는 `}`까지 읽고,
 * `@keyframes` 같은 중첩 블록 안의 내용은 뺀다. 주석이나 문자열 안의 중괄호는 없다고 가정한다.
 */
function getTopLevelBlock({ css, selector }: { css: string; selector: string }): string {
  const start = css.indexOf(`${selector} {`);
  if (start === -1) throw new Error(`tokens.css에 ${selector} 블록이 없다.`);
  let depth = 0;
  let topLevel = '';
  for (let i = css.indexOf('{', start); i < css.length; i++) {
    const char = css[i];
    if (char === '{') depth++;
    else if (char === '}') {
      depth--;
      if (depth === 0) return topLevel;
    } else if (depth === 1) topLevel += char;
  }
  throw new Error(`tokens.css의 ${selector} 블록이 닫히지 않았다.`);
}
  1. 시작 찾기 ':root {'라는 글자가 처음 나오는 위치를 indexOf로 찾는다.
  2. 깊이 세기 그 뒤의 {부터 한 글자씩 읽으며 {에서 깊이를 1 올리고 }에서 1 내린다.
  3. 최상위만 모으기 깊이가 1일 때의 글자만 모은다. @keyframes 안(깊이 2 이상)의 내용은 빠진다.
  4. 끝내기 깊이가 다시 0이 되는 }, 즉 짝이 맞는 닫는 괄호에서 모은 글자를 돌려준다.
  • '@theme {'로 찾으므로 아래쪽의 @theme inline {는 걸리지 않는다. @theme과 { 사이에 inline이 끼어 있어 글자가 일치하지 않기 때문이다.
  • 블록을 못 찾거나 닫히지 않으면 에러를 던진다. 누가 블록 이름을 바꿨을 때 토큰 화면이 빈 표를 조용히 보여 주는 대신 바로 깨진다.
  • 처음에는 첫 }에서 잘랐다. #22에서 로딩 애니메이션의 @keyframes를 Tailwind 권장대로 @theme 안에 두면서, 그 뒤의 토큰이 사라지지 않도록 깊이를 세는 방식으로 바꿨다.

parseDeclarations: 이름과 값 뽑기

const declaration = /--([\w-]+):\s*([^;]+);/g;

function parseDeclarations(block: string): [string, string][] {
  return [...block.matchAll(declaration)].map((m) => [m[1]!, m[2]!.trim()]);
}

정규식을 조각내 --blue-500: #3182f6;에 대 보면 이렇다.

조각 뜻 일치하는 부분
-- 글자 그대로 -- --
([\w-]+) 첫 번째 캡처. 글자·숫자·_·-가 1개 이상 blue-500
:\s* 콜론과 뒤따르는 공백 :
([^;]+) 두 번째 캡처. ;가 아닌 글자 1개 이상 #3182f6
; 선언의 끝 ;

g 플래그를 붙인 정규식을 matchAll에 넘기면 블록 안의 모든 일치를 차례로 돌려준다. 각 일치에서 캡처 두 개(m[1], m[2])만 꺼내 쌍으로 만든다. 

parseDeclarations(':root { --grey-50: #f9fafb; --blue-500: #3182f6; }');
// → [['grey-50', '#f9fafb'], ['blue-500', '#3182f6']]

--color-*: initial;은 *가 [\w-]에 없어 아예 일치하지 않고 건너뛴다. Tailwind 기본값을 지우는 줄이 표에 끼지 않는 첫 번째 이유다.

filterThemeValues: 종류별로 고르기

@theme의 선언에는 색, 글자 크기, 간격, 모서리가 섞여 있다. 접두어로 한 종류만 고르고 이름을 다듬는다. 

function filterThemeValues({
  theme,
  prefix,
}: {
  theme: [string, string][];
  prefix: string;
}): ThemeValue[] {
  return theme
    .filter(([name, value]) => name.startsWith(prefix) && value !== 'initial') // ① 고르기
    .map(([name, value]) => ({ name: name.slice(prefix.length), value }))     // ② 접두어 떼기
    .filter(({ name }) => !name.includes('--'));                              // ③ 딸린 설정 빼기
}

prefix: 'text-'로 따라가 보면 이렇다.

입력 ① 고르기 ② 접두어 떼기 ③ 딸린 설정 빼기
['color-primary', 'var(--blue-500)'] 탈락
['text-caption', '0.75rem'] 통과 caption 남음
['text-caption--line-height', '1.5'] 통과 caption--line-height 탈락 -- 포함
['spacing-lg', '1rem'] 탈락
  • ③이 필요한 이유: Tailwind v4에서 --text-caption--line-height는 별도 토큰이 아니라 text-caption 클래스에 딸린 줄 높이 설정이다. 표에는 caption 한 줄만 나와야 한다.
  • ①의 value !== 'initial'은 방어용이다. 지금 파일에서 initial로 지우는 줄은 정규식 단계에서 빠지거나(--color-*), 접두어가 달라 여기까지 오지 않는다 (--spacing: initial의 이름은 spacing이라 spacing-로 시작하지 않는다). 나중에 --radius-card: initial;처럼 토큰 하나를 지우는 줄이 생겨도 표에 끼지 않게 막아 둔 것이다.

의미 토큰을 팔레트에 잇기

readTokens는 먼저 팔레트로 "이름 → hex" 사전을 만들고, 의미 색의 값이 var(--무엇) 꼴이면 그 무엇을 사전에서 찾는다. 

const palette = parseDeclarations(getTopLevelBlock({ css, selector: ':root' })).map(([name, hex]) => ({
  name,
  hex,
}));
const hexByName = new Map(palette.map((p) => [p.name, p.hex])); // hexByName.get('blue-500') === '#3182f6'
const theme = parseDeclarations(getTopLevelBlock({ css, selector: '@theme' }));

const colors = filterThemeValues({ theme, prefix: 'color-' }).map(({ name, value }) => {
  const ref = /^var\(--([\w-]+)\)$/.exec(value)?.[1] ?? null;
  return { name, palette: ref, hex: ref ? (hexByName.get(ref) ?? value) : value };
});
의미 토큰 value ref 결과
primary var(--blue-500) blue-500 { palette: 'blue-500', hex: '#3182f6' } 사전에서 찾음
surface #ffffff null { palette: null, hex: '#ffffff' } 값 그대로
  • ^와 $가 처음과 끝을 고정하므로 값 전체가 var(--무엇)일 때만 일치한다. var(--a, #fff)나 color-mix(...)는 연결이 없는 값으로 본다.
  • hexByName.get(ref) ?? value는 팔레트에 없는 이름을 가리킬 때(오타 등) 값 문자열이라도 보여 주는 대비책이다.

출력

{
  palette:   [{ name: 'grey-50', hex: '#f9fafb' }, /* ... 80개 */],
  colors:    [{ name: 'primary', palette: 'blue-500', hex: '#3182f6' }, /* ... */],
  textSizes: [{ name: 'caption', value: '0.75rem' }, /* ... */],
  spacing:   [{ name: 'lg', value: '1rem' }, /* ... */],
  radii:     [{ name: 'card', value: '12px' }, /* ... */],
}

토큰 화면은 이 객체를 map으로 돌며 표를 그린다. cn.spec.ts는 textSizes, spacing, radii의 이름을 돌며 cn의 tailwind-merge 설정에 빠진 토큰이 없는지 확인한다.

가정과 한계

이 파서는 tokens.css가 지금 모양을 지킨다고 가정한다. 가정이 깨지면 에러 없이 값이 빠질 수 있다.

가정 깨지면
주석이나 문자열 안에 짝이 맞지 않는 중괄호가 없다 주석 속 } 하나에서 블록이 일찍 끝나 그 뒤의 토큰이 표에서 사라진다. 짝이 맞는 { }나 @keyframes 같은 중첩 블록은 괜찮다.
선언은 --이름: 값; 한 꼴이다 ; 없이 끝나는 마지막 선언은 일치하지 않아 빠진다.
의미 색은 var(--팔레트) 하나로 잇는다 다른 꼴의 값은 팔레트 열이 -로 나온다.
주석 안에 --이름: 값;이 없다 주석 속 예시가 토큰처럼 표에 낀다.

그래도 PostCSS 같은 정식 파서를 들이지 않았다. 가정이 깨지면 토큰 화면에서 바로 드러나고, tokens.css는 사람이 손으로 관리하는 파일 하나뿐이라 모양을 지키기 쉽다.

우리 프로젝트에서는

  • 값의 출처는 tokens.css 하나다. 스토어는 이 파일을 Tailwind로 불러오고, 토큰 화면과 cn 테스트는 이 파서로 같은 파일을 읽는다.
  • 토큰 화면의 예시(간격 막대, 글자 크기, 모서리)는 var(--spacing-md) 대신 파서가 읽은 값(0.75rem)을 인라인 스타일에 직접 쓴다. Tailwind v4는 클래스로 쓰인 테마 변수만 CSS에 내보내므로, 아무 데서도 p-md 같은 클래스로 쓰지 않은 토큰은 변수가 없다. 처음에 변수를 참조했을 때 --spacing-md, --spacing-2xl이 없어 간격 막대가 전체 폭으로 늘어났고, text-title과 rounded-button도 조용히 틀린 모습이었다.
  • Vitest는 기본으로 CSS import를 빈 문자열로 바꾼다. ?raw를 붙여도 마찬가지라, 처음에는 테스트에서 ":root 블록이 없다" 에러가 났다. 그래서 packages/store-ui/vitest.config.ts에서 css: { include: [/tokens\.css/] }로 이 파일만 살렸다.
  • 파서 테스트는 read-tokens.spec.ts 하나다. @theme 중간에 @keyframes가 있어도 그 뒤의 토큰을 읽는지 확인한다. 그 밖에는 cn.spec.ts가 파서 결과를 쓰므로, 파서가 토큰을 빠뜨리면 그쪽 테스트 개수가 줄어드는 식으로 간접적으로 드러난다.

스스로 확인하기

1. getComputedStyle로는 왜 토큰 화면의 "팔레트" 열을 채울 수 없나?

브라우저는 계산된 값만 돌려준다. --color-primary를 읽으면 var(--blue-500)가 이미 풀린 #3182f6이 나오므로, 어떤 팔레트 변수를 거쳤는지 알 수 없다. 원문에만 그 연결이 글자로 남아 있다.

2. @theme 블록 맨 위에 "/* 닫는 괄호 } 주의 */" 주석을 넣으면 토큰 화면은 어떻게 되나?

getTopLevelBlock가 주석 속 }에서 깊이가 0이 되어 블록을 끝낸다. 그 뒤의 모든 의미 토큰이 빠져 색, 글자 크기, 간격, 모서리 표가 비거나 줄어든다. 에러는 나지 않는다. 블록 시작을 찾았고 닫는 괄호도 만났기 때문이다. cn.spec.ts도 돌 토큰이 없어 해당 테스트가 사라진다. /* 예: { a: b } */처럼 짝이 맞는 괄호는 깊이 2로 들어갔다 나오므로 괜찮다.

3. --text-caption--line-height가 글자 크기 표에 나오지 않는 것은 어느 줄 덕분인가?

filterThemeValues의 마지막 filter(({ name }) => !name.includes('--'))다. 접두어 text-를 떼고 남은 caption--line-height에 --가 있어 빠진다.

4. 의미 색을 --color-primary: var(--blue-50O); 처럼 오타(숫자 0 대신 영문 O)로 적으면?

정규식은 blue-50O를 ref로 뽑지만 사전에 없다. 그래서 hexByName.get(ref) ?? value가 값 문자열 var(--blue-50O)를 hex 자리에 보여 준다. 스와치 색은 브라우저가 해석하지 못해 투명해지므로 화면에서 바로 눈에 띈다.
