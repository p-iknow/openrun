cn과 tailwind-merge 확장: clsx, twMerge, extendTailwindMerge

@openrun/store-ui의 cn은 clsx와 tailwind-merge를 이어 붙인 함수다. 두 라이브러리가 각각 무엇을 하는지, 왜 tailwind-merge에 우리 토큰 이름을 알려 줘야 하는지, extendTailwindMerge로 할 수 있는 확장을 모두 정리한다. 예시의 결과는 tailwind-merge@3.7.0, clsx@2.1.1에서 실행해 확인한 값이다.

한눈에 보기

// packages/store-ui/src/cn.ts
export function cn(...inputs: ClassValue[]): string {
  return twMerge(clsx(inputs));
}
cn('p-lg', active && 'bg-primary', className)
  1. clsx: 참인 것만 이어 붙임
  2. twMerge: 부딪히면 뒤의 것만 남김
  3. className 문자열
이름 하는 일 모르는 것
clsx 여러 클래스를 조건에 따라 하나의 문자열로 이어 붙인다 클래스의 내용. p-2와 p-4가 부딪힌다는 사실
tailwind-merge 서로 부딪히는 Tailwind 클래스 중 뒤의 것만 남긴다 설정에 없는 이름. 우리가 만든 토큰 이름
cn 위 두 개를 순서대로 부른다

clsx: 조건부로 이어 붙이기

clsx는 문자열, 객체, 배열, falsy 값을 받아 참인 것만 공백으로 이어 붙인다.

clsx('a', false && 'b', null, { c: true, d: false }, ['e', ['f']]);
// → "a c e f"
  • 'a'는 그대로 넣는다.
  • false, null, undefined, 0, ''는 버린다.
  • 객체는 값이 참인 키만 넣는다.
  • 배열은 중첩돼도 펼쳐서 넣는다.

템플릿 문자열로 조건부 클래스를 쓰면 빈 문자열과 공백이 남고 읽기 어렵다.

// clsx 없이
className={`p-lg ${active ? 'bg-primary' : ''} ${disabled ? 'opacity-50' : ''}`}

// clsx로
className={clsx('p-lg', active && 'bg-primary', { 'opacity-50': disabled })}

clsx는 내용을 보지 않는다. clsx('p-2', 'p-4')는 "p-2 p-4"를 그대로 돌려준다.

tailwind-merge: 충돌 정리

p-2 p-4가 함께 붙어 있으면, 어느 쪽이 이길지는 className에 적은 순서가 아니라 생성된 CSS 안의 규칙 순서로 정해진다. 컴포넌트가 기본 클래스를 갖고 밖에서 className을 받을 때 이 점이 문제가 된다. 

function Badge({ className }: { className?: string }) {
  return <span className={clsx('p-sm bg-surface', className)} />;
}

<Badge className="bg-primary" />
// clsx만 쓰면 "p-sm bg-surface bg-primary": 어느 배경이 이길지 모른다

tailwind-merge는 클래스를 건드리는 CSS 속성에 따라 그룹으로 나누고, 같은 그룹이면 뒤의 것만 남긴다. 

twMerge('p-sm bg-surface', 'bg-primary'); // → "p-sm bg-primary"
twMerge('p-2', 'p-4');                    // → "p-4"
twMerge('px-4', 'p-2');                   // → "p-2"       p가 px를 포함하므로 px를 지운다
twMerge('p-2', 'px-4');                   // → "p-2 px-4"  px는 p의 일부만 덮으므로 둘 다 둔다

그래서 컴포넌트를 쓰는 쪽이 className으로 기본 스타일을 안전하게 덮어쓸 수 있다.

확장이 필요한 이유

tailwind-merge는 CSS를 읽지 않는다. 미리 들고 있는 Tailwind 기본 이름 목록을 보고 클래스의 그룹을 추측한다.

tokens.css의 @theme은 Tailwind 기본값을 지우고 caption, lg, card 같은 의미 이름만 노출한다. tailwind-merge는 이 이름들을 모르므로 판단을 틀린다.

입력 기본 twMerge 확장한 twMerge 무엇이 문제인가
text-caption text-text text-text text-caption text-text 지움 caption을 모르니 글자색으로 보고, 글자색 text-text와 부딪힌다고 판단해 글자 크기를 지운다
p-sm p-lg p-sm p-lg p-lg 못 정리함 sm, lg를 간격으로 모른다
px-lg p-sm px-lg p-sm p-sm 못 정리함 위와 같다
rounded-card rounded-button 둘 다 남음 rounded-button 못 정리함 모서리 값으로 모른다

첫 줄이 가장 위험하다. 글자 크기와 글자색이 모두 text- 접두사를 쓰기 때문에, 에러 없이 스타일이 조용히 사라진다. 나머지는 정리를 못 할 뿐이지만, 이 경우는 필요한 클래스를 지운다.

색 이름(text-primary, bg-surface)은 따로 알려 주지 않아도 맞게 동작한다. tailwind-merge가 "모르는 text-*, bg-*는 색"으로 처리하기 때문이다. 문제는 색이 아닌데 text-를 쓰는 글자 크기 쪽이다.

theme: 토큰 이름 알려 주기

const twMerge = extendTailwindMerge({
  extend: {                 // 기본 설정을 버리지 않고 덧붙인다
    theme: {
      text: ['caption', 'body-sm', 'body', 'title', 'heading', 'display'], // text-*  글자 크기
      spacing: ['xs', 'sm', 'md', 'lg', 'xl', '2xl', '3xl'],                // p-*, m-*, gap-* …
      radius: ['badge', 'card', 'button', 'panel'],                        // rounded-*
      shadow: ['floating'],                                                // shadow-*
      container: ['content'],                                              // max-w-* 등
    },
  },
});
  • theme의 키는 Tailwind v4 @theme 변수의 이름 공간과 짝을 맞춘다. --text-caption이 있으면 text: ['caption'], --spacing-lg가 있으면 spacing: ['lg']다.
  • 한 키에 이름을 넣으면 그 키를 쓰는 모든 클래스 그룹에 반영된다. spacing에 lg를 넣으면 p-lg, mx-lg, gap-lg, space-y-lg가 한 번에 인식된다. 그룹을 하나씩 등록하는 것보다 간단하다.

먼저 알아 둘 개념

tailwind-merge는 클래스 하나를 다음 순서로 처리한다.

  1. 수식어 분리 hover:p-4를 수식어 [hover]와 본체 p-4로 나눈다.
  2. 그룹 찾기 p-4가 p(padding) 그룹이라는 것을 찾는다.
  3. 충돌 판단 앞쪽에 같은 수식어를 가진 같은 그룹, 또는 충돌 관계인 그룹의 클래스가 있으면 그 클래스를 지운다.
개념 뜻 예
클래스 그룹 같은 CSS 속성을 건드리는 클래스 묶음. ID가 붙어 있다 'p', 'px', 'font-size', 'text-color'
theme 여러 그룹이 함께 쓰는 값 목록 spacing을 p, m, gap 그룹이 함께 쓴다
validator 값이 맞는지 판단하는 함수 isNumber, isArbitraryValue

설정은 두 층으로 나뉜다.

extendTailwindMerge({
  // 바깥 층: 동작 방식
  prefix: 'tw',
  cacheSize: 500,
  experimentalParseClassName: ...,

  // 안쪽 층: 그룹과 충돌 규칙 (extend는 덧붙이기, override는 갈아끼우기)
  extend:   { theme, classGroups, conflictingClassGroups, conflictingClassGroupModifiers, orderSensitiveModifiers },
  override: { theme, classGroups, conflictingClassGroups, conflictingClassGroupModifiers, orderSensitiveModifiers },
});

classGroups: 새 클래스 그룹 만들기

Tailwind에 없는 클래스를 직접 만들었을 때 쓴다. 예를 들어 tokens.css에 @utility elevation-*를 정의한 경우다. 

// 설정 없음
twMerge('elevation-1', 'elevation-3'); // → "elevation-1 elevation-3"  모르는 클래스라 그냥 둔다

// 설정 있음
const twMerge = extendTailwindMerge({
  extend: {
    classGroups: {
      elevation: [{ elevation: ['1', '2', '3', 'none'] }],
    },
  },
});
twMerge('elevation-1', 'elevation-3'); // → "elevation-3"

그룹을 정의하는 네 가지 방식

classGroups: {
  // ① 정확한 문자열: 클래스 이름 전체를 나열한다
  skin: ['skin-light', 'skin-dark'],

  // ② 객체: { 접두사: [뒤에 올 값들] } → elevation-1, elevation-2 …
  elevation: [{ elevation: ['1', '2', '3'] }],

  // ③ validator: 값을 함수로 검사한다
  stagger: [{ stagger: [validators.isNumber] }],
  //   stagger-1, stagger-20은 인식하고 stagger-abc는 인식하지 않는다

  // ④ fromTheme: theme 목록을 가져다 쓴다
  gutter: [{ gutter: [fromTheme('spacing')] }],
  //   theme.spacing에 넣은 'lg', 'sm'이 그대로 쓰여 gutter-lg, gutter-sm이 된다
}

④가 중요하다. theme.spacing에 의미 이름을 넣어 두었다면, 직접 만든 유틸리티도 fromTheme('spacing')으로 연결해 토큰 목록을 한 곳에서만 관리할 수 있다.

선택 읽기: 자주 쓰는 validator

import { validators } from 'tailwind-merge'로 가져온다.

이름 통과하는 예
isNumber1, 20, 1.5
isInteger1, 20
isFraction1/2, 3/4
isArbitraryValue[10px], [var(--x)]
isArbitraryVariable(--my-var)
isTshirtSizesm, xl, 2xl
isAny무엇이든

기존 그룹에 값을 추가하기

새 ID 대신 기존 ID를 쓰면 기존 그룹에 덧붙여진다.

extend: {
  classGroups: {
    'font-size': [{ text: ['caption', 'body'] }], // 기존 font-size 그룹에 추가
  },
}

theme의 text로 한 일을 그룹 단위로 직접 하는 셈이다. 기본 그룹 ID 목록은 node_modules/tailwind-merge/dist/types.d.ts의 DefaultClassGroupIds에 있다.

새 그룹을 만들기 전에 기본 설정이 이미 아는지 확인한다. 예를 들어 text-shadow-*는 Tailwind v4.1에 들어가서 tailwind-merge 기본 설정이 이미 처리한다.

conflictingClassGroups: 다른 그룹끼리 충돌시키기

한 클래스가 다른 그룹의 효과까지 덮어쓸 때 쓴다. 기본 설정의 대표적인 예가 p와 px다. 서로 다른 그룹이지만 p가 px를 덮는다. 

twMerge('px-2', 'p-4'); // → "p-4"

그림자와 elevation을 모두 없애는 flat 클래스를 만들었다고 하자.

classGroups: {
  elevation: [{ elevation: ['1', '2', '3'] }],
  flat: ['flat'],
},

// 관계를 알려 주지 않으면
twMerge('elevation-2', 'flat');           // → "elevation-2 flat"  다른 그룹이라 둘 다 둔다

// 관계를 알려 주면
conflictingClassGroups: {
  flat: ['elevation', 'shadow'],          // flat이 오면 앞의 elevation, shadow를 지운다
},
twMerge('elevation-2 shadow-lg', 'flat'); // → "flat"

한 방향으로만 적용된다. 키(flat)가 뒤에 올 때만 값(elevation, shadow)을 지운다. twMerge('flat', 'elevation-2')는 "flat elevation-2"다. p와 px가 비대칭인 것과 같은 원리다. 양쪽으로 지우려면 두 방향을 모두 적는다.

conflictingClassGroupModifiers: / 뒤의 값이 다른 그룹을 덮을 때

text-lg/8처럼 / 뒤에 붙는 값(postfix modifier)이 다른 속성까지 정할 때 쓴다. text-lg/8은 글자 크기와 줄 높이를 함께 정한다. 기본 설정에 { 'font-size': ['leading'] }가 들어 있어서 다음처럼 동작한다. 

twMerge('leading-7', 'text-lg/8'); // → "text-lg/8"

elevation-2/blue가 그림자 색까지 정하는 유틸리티라면 이렇게 알려 준다.

conflictingClassGroupModifiers: {
  elevation: ['elevation-color'], // elevation에 /값이 붙어 있으면 앞의 elevation-color를 지운다
},

twMerge('elevation-tint-red', 'elevation-2/blue'); // → "elevation-2/blue"
twMerge('elevation-tint-red', 'elevation-2');      // → "elevation-tint-red elevation-2"  /가 없으면 지우지 않는다

conflictingClassGroups와 다른 점은 /가 붙었을 때만 작동한다는 것이다.

orderSensitiveModifiers: 수식어 순서가 의미를 바꿀 때

보통 수식어 순서는 상관없어서 tailwind-merge도 같은 것으로 본다.

twMerge('hover:focus:p-2', 'focus:hover:p-4'); // → "focus:hover:p-4"

before:, after:, *: 같은 수식어는 순서에 따라 대상 요소가 바뀐다. before:hover:는 "가상 요소에 hover"이고, hover:before:는 "hover했을 때의 가상 요소"다. 

twMerge('before:hover:p-2', 'hover:before:p-4'); // → 둘 다 남긴다

기본 목록은 *, **, after, backdrop, before, details-content, file, first-letter, first-line, marker, placeholder, selection이다. @custom-variant로 특정 자식이나 가상 요소를 가리키는 variant를 만들었을 때 추가한다. 

extend: { orderSensitiveModifiers: ['thumb'] } // 예: 슬라이더 손잡이를 가리키는 thumb: variant

extend와 override

같은 키를 넣어도 결과가 크게 다르다.

const e = extendTailwindMerge({ extend:   { theme: { spacing: ['lg', 'sm'] } } });
const o = extendTailwindMerge({ override: { theme: { spacing: ['lg', 'sm'] } } });

e('p-2', 'p-4');   // → "p-4"      기본 숫자 간격도 그대로 안다
o('p-2', 'p-4');   // → "p-2 p-4"  기본값이 사라져 숫자 간격을 모른다
o('p-sm', 'p-lg'); // → "p-lg"
extend override
동작 기존 배열 뒤에 추가 그 키의 값을 통째로 교체
위험도 낮다 높다. 기본 동작을 깨뜨릴 수 있다
쓰는 경우 거의 항상 Tailwind 기본값을 정말로 금지했고, merge에서도 그것을 확실히 반영해야 할 때

둘을 함께 쓰면 override를 먼저, extend를 나중에 적용한다.

이 저장소는 @theme에서 기본값을 지웠으니 override가 더 정확해 보일 수 있다. 하지만 theme.spacing을 갈아끼우면 임의 값 처리 같은 기본 동작까지 영향받을 수 있다. 얻는 것에 비해 위험이 커서 extend를 쓴다.

prefix와 cacheSize

prefix

CSS에서 @import "tailwindcss" prefix(tw);로 접두사를 붙였다면 merge에도 알려 준다.

const twMerge = extendTailwindMerge({ prefix: 'tw' });

twMerge('tw:p-2', 'tw:p-4'); // → "tw:p-4"
twMerge('p-2', 'p-4');       // → "p-2 p-4"  접두사가 없으면 Tailwind 클래스로 보지 않는다

v4 문법은 tw:p-2처럼 콜론을 쓴다. v3의 tw-p-2와 다르다.

cacheSize

같은 입력 문자열은 결과를 LRU 캐시에 저장해 다시 쓴다. 기본값은 500이고, 0 이하이면 캐시를 쓰지 않는다. 서로 다른 클래스 조합이 아주 많을 때만 늘린다.

experimentalParseClassName: 클래스 해석 바꾸기

마이너 버전에서도 바뀔 수 있다고 명시된 실험 기능이다.

처리 순서의 첫 단계(수식어 분리)를 직접 가로챈다. 아래는 특정 클래스를 merge 대상에서 빼는 예다. 

const twMerge = extendTailwindMerge({
  experimentalParseClassName({ className, parseClassName }) {
    if (MUST_KEEP.has(className)) {
      return {
        isExternal: true,
        modifiers: [],
        hasImportantModifier: false,
        baseClassName: className,
        maybePostfixModifierPosition: undefined,
      };
    }
    return parseClassName(className); // 나머지는 기본 해석
  },
});
반환 필드 뜻
isExternaltrue이면 이 클래스는 지우지도, 다른 클래스를 지우지도 않는다
modifiers['hover', 'dark']처럼 수식어 목록
baseClassName수식어를 뗀 본체
hasImportantModifier!가 붙었는지
maybePostfixModifierPosition/ 뒤 값이 시작하는 위치

일반적인 앱에서는 거의 쓰지 않는다. 접두사 규칙이 특이한 라이브러리를 만들 때 쓰는 탈출구다.

설정을 넣는 다른 방법

함수로 넘기기

객체 대신 기본 설정을 받아 고치는 함수를 넘길 수 있다. 여러 개를 넘기면 순서대로 적용한다. 객체로 표현하기 어려운 조작, 예를 들어 기존 그룹에서 특정 값을 빼는 일에 쓴다. 

const twMerge = extendTailwindMerge(
  { extend: { theme: { spacing: ['lg'] } } }, // 객체는 항상 첫 번째 자리
  (config) => {
    config.classGroups['skin'] = ['skin-a', 'skin-b'];
    return config;
  },
);

createTailwindMerge: 처음부터 만들기

기본 설정 없이 완전히 빈 상태에서 만든다.

const twMerge = createTailwindMerge(() => ({
  cacheSize: 0,
  theme: {},
  classGroups: { pad: [{ pad: ['1', '2'] }] },
  conflictingClassGroups: {},
  conflictingClassGroupModifiers: {},
  orderSensitiveModifiers: [],
}));

twMerge('pad-1', 'pad-2'); // → "pad-2"
twMerge('p-2', 'p-4');     // → "p-2 p-4"  Tailwind 기본 클래스는 전혀 모른다

Tailwind가 아닌 자체 유틸리티 체계를 쓸 때만 의미가 있다. createTailwindMerge(() => mergeConfigs(getDefaultConfig(), {...}))처럼 조합하면 사실상 extendTailwindMerge가 내부에서 하는 일이 된다.

선택 읽기: 함께 export되는 도구들
이름 용도

우리 프로젝트에서는

상황 쓸 옵션

토큰을 tokens.css에만 추가하고 cn.ts에 빠뜨리면 조용히 사라지는 버그가 생긴다. 그래서 cn.spec.ts는 008 문서의 파서로 tokens.css를 직접 읽고, 모든 글자 크기, 간격, 모서리 토큰마다 확인한다. 

it.each(tokens.textSizes.map((t) => t.name))(
  '글자 크기 text-%s와 글자색 text-text를 함께 남긴다',
  (size) => {
    expect(cn(`text-${size}`, 'text-text')).toBe(`text-${size} text-text`);
  },
);

그림자와 최대 폭은 토큰 목록을 도는 테스트가 없다. tokens.css에 추가하면 cn.ts에도 직접 추가해야 한다. 나중에 @utility를 추가하면 classGroups를 등록하고 cn.spec.ts에 "뒤의 것만 남는다" 테스트를 함께 추가한다.

스스로 확인하기

1. cn에서 clsx를 빼고 twMerge만 쓰면 무엇을 잃나?

twMerge도 문자열 여러 개와 falsy 값은 받지만, { 'bg-primary': active } 같은 객체 문법은 받지 않는다. 조건부 클래스를 객체로 쓰는 편의를 잃는다. 반대로 clsx만 쓰면 컴포넌트 밖에서 넘긴 className이 기본 클래스를 확실히 덮지 못한다.

2. tokens.css에 --text-overline을 추가하고 cn.ts를 고치지 않으면 어떤 화면 버그가 생기나?

cn('text-overline', 'text-text')가 "text-text"가 된다. tailwind-merge가 overline을 글자색으로 보고 뒤의 글자색과 부딪힌다고 판단하기 때문이다. 에러 없이 글자 크기만 기본값으로 돌아간다. cn.spec.ts가 tokens.css를 읽어 돌기 때문에 이 테스트가 실패해 알려 준다.

3. conflictingClassGroups에 { flat: ['elevation'] }만 적었을 때 cn('flat', 'elevation-2')의 결과는?

"flat elevation-2"다. 충돌 규칙은 키 쪽 클래스가 뒤에 올 때만 앞의 값 쪽 클래스를 지운다. 반대 방향도 지우려면 elevation: ['flat']도 적어야 한다.

4. theme.spacing을 extend 대신 override로 바꾸면 cn('p-2', 'p-4')는 어떻게 되나?

"p-2 p-4"다. override가 기본 간격 목록을 지워서 숫자 간격을 padding으로 인식하지 못한다. 우리 @theme에서 숫자 간격을 지웠더라도, merge 동작이 바뀐다는 점은 알고 골라야 한다.
