Button으로 보는 Tailwind 배치와 상태 패턴

packages/store-ui/src/button.tsx에 쓰인 Tailwind 패턴을 정리한다. 다루는 것은 inline-flex, relative와 absolute inset-[0], group, data-*와 not-* 변형, motion-safe, 애니메이션 토큰이다. CSS 예시는 스토어 빌드(Tailwind 4.3)가 실제로 만든 결과를 옮겨 적었다.

한눈에 보기

로딩 중인 Button의 구조다. 패턴마다 아래 절에서 하나씩 다룬다.

  • button group relative inline-flex items-center justify-center와 data-loading, data-disabled 속성
    • span (라벨) group-data-loading:opacity-0. 흐름 안에 남아 버튼 폭을 정한다
    • span (오버레이) absolute inset-[0] flex items-center justify-center. 버튼 전체를 덮는다
      • span × 3 (점) motion-safe:animate-loading-dot, 지연 0 / 160 / 320ms
패턴 푸는 문제
inline-flex 버튼이 내용 폭만 차지하고, 고정 높이 안에서 라벨을 가운데에 둔다
relative + absolute inset-[0] 폭을 바꾸지 않고 버튼 위에 같은 크기의 상자를 겹친다
group + group-data-* 버튼의 상태 속성을 보고 자식(라벨)의 스타일을 바꾼다
data-*, not-data-* Base UI가 붙이는 상태 속성으로 스타일을 정하고, 겹치는 상태를 가른다
motion-safe 움직임 줄이기를 켠 사용자에게는 반복 애니메이션을 끈다

inline-flex: 내용 폭과 가운데 정렬

inline-flex는 두 성질을 합친 값이다.

값 바깥에서 보면 안쪽에서 보면
flex block: 부모 폭을 다 채우고 앞뒤로 줄이 바뀐다 자식을 flex로 배치
inline-flex inline: 내용 폭만 차지하고 글자나 다른 버튼 옆에 나란히 선다 자식을 flex로 배치
  • 바깥은 inline이라, 홈 소개 영역의 새로고침 버튼은 줄 전체가 아니라 글자 폭만큼만 차지한다.
  • 안쪽은 flex라서 items-center로 높이 52px 안의 세로 가운데, justify-center로 가로 가운데에 라벨을 둔다. 브라우저의 <button>도 기본으로 세로 가운데에 두지만, 브라우저마다 다를 수 있어 flex로 명시한다.

자식이 글자 하나뿐이면 그 자식에게 flex나 gap을 줄 이유가 없다. gap은 flex 항목 사이의 간격이라 항목이 하나면 효과가 없다. 라벨 span에 있던 inline-flex items-center gap-sm은 아이콘을 함께 넣을 경우를 미리 대비한 것이라 뺐다.

relative와 absolute inset: 겹치기

.relative   { position: relative; }   /* 버튼: 기준이 된다 */
.absolute   { position: absolute; }   /* 오버레이: 흐름에서 빠진다 */
.inset-\[0\] { inset: 0; }            /* top·right·bottom·left를 모두 0으로 */
  1. 흐름에서 빼기 absolute 요소는 다른 요소의 자리를 차지하지 않는다. 그래서 버튼 폭은 계속 라벨 글자 폭으로 정해진다.
  2. 기준 정하기 위치는 가장 가까운, position이 static이 아닌 조상을 기준으로 정한다. 버튼에 relative를 붙여 기준을 버튼으로 만든다.
  3. 네 변에 붙이기 inset: 0은 기준 요소의 네 변에 붙인다. 결과적으로 버튼과 같은 크기의 상자가 버튼 위에 겹친다. 덮는 범위는 기준 요소의 padding 영역까지이고 border는 덮지 않는다.
  • 기준이 없으면, 즉 버튼에 relative가 없으면 오버레이는 바깥 조상을 덮는다. 그런 조상이 하나도 없으면 첫 화면 크기의 상자(초기 포함 블록)를 기준으로 삼는다.
  • 오버레이에 배경을 칠한다면 모서리도 맞춰야 한다. rounded-button은 버튼에만 걸려 있으므로, 오버레이에 같은 모서리를 주거나 버튼에 overflow-hidden을 준다. 지금 오버레이는 투명해서 상관없다.
  • 라벨을 지우지 않고 opacity-0으로 투명하게만 만드는 것도 같은 목적이다. 라벨을 지우면 로딩이 시작될 때 버튼 폭이 줄었다가 끝나면 다시 늘어나 주변 레이아웃이 흔들린다. 투명한 글자는 스크린 리더가 읽는 버튼 이름으로도 그대로 남는다. invisible(visibility: hidden)은 이름까지 지운다.

우리 토큰에서는 inset-0이 생성되지 않는다. Tailwind v4의 숫자 간격 클래스는 calc(var(--spacing) * 0)처럼 --spacing으로 계산한다. 그런데 tokens.css가 --spacing: initial로 이 값을 지웠기 때문에 값이 0이어도 만들어지지 않는다. 처음 Button에 inset-0을 썼을 때 오버레이는 버튼을 덮지 않았다. 그래도 점이 가운데에 보인 것은, flex 컨테이너 안의 absolute 요소가 위치 값이 없으면 justify-center와 items-center를 따른 자리에 놓이기 때문이었다. 화면만 봐서는 알 수 없었고, 생성된 CSS를 확인하고서야 드러났다. 그래서 임의값 inset-[0]으로 바꿨다.

group: 조상 상태로 자식 꾸미기

보통 클래스는 그 요소 자신의 상태(hover:, data-loading:)만 본다. 조상의 상태를 보려면 조상에 group을 붙이고 자식에 group-*: 변형을 쓴다. 

<BaseButton data-loading={isLoading || undefined} className="group ...">
  <span className="group-data-loading:opacity-0">{children}</span>
/* 생성된 CSS */
:is(:where(.group)[data-loading] .group-data-loading\:opacity-0) { opacity: 0; }
  • "group 클래스가 있고 data-loading 속성이 있는 조상 아래의 이 요소"라는 뜻이다. group 자체는 스타일이 없는 표시용 클래스다.
  • :where() 안의 선택자는 우선순위에 더해지지 않는다. 그래서 .group은 빠지고 [data-loading]과 자기 클래스만 계산된다. 조상에 group을 붙였다고 규칙이 더 강해지지는 않는다.
  • group-hover:, group-focus-visible:, group-data-[state=open]:처럼 다른 상태에도 쓴다. 카드 전체에 마우스를 올리면 제목 색이 바뀌는 효과가 대표적인 예다.
  • group이 중첩되면 가장 가까운 것이 아니라 어느 조상이든 걸린다. 이를 피하려면 group/card와 group-hover/card:처럼 이름을 붙인다.
  • 형제 요소의 상태를 볼 때는 peer와 peer-*:를 쓴다. 예를 들어 앞에 오는 input이 :invalid일 때 뒤의 안내문을 빨갛게 바꾼다.

Button에서는 렌더링할 때 이미 isLoading을 알고 있으므로 group 없이도 같은 결과를 낼 수 있다. 

<span className={isLoading ? 'opacity-0' : undefined}>{children}</span>
방식 장점 단점
group-data-loading: (지금) 스타일이 DOM 속성 하나에 묶이고, 버튼의 다른 상태 스타일(data-disabled:)과 같은 방식이다 group을 모르면 읽기 어렵다
isLoading ? ... : ... JS만 보면 바로 이해된다 상태 스타일이 CSS 속성 방식과 JS 조건 방식으로 섞인다

JS 조건 방식을 쓸 수 없는 경우가 있다. 상태를 Base UI가 안에서 관리해서 컴포넌트 코드가 그 값을 모를 때다. 예를 들어 Select가 열렸는지에 따라 화살표 아이콘을 돌리려면 group-data-[popup-open]:rotate-180처럼 속성을 봐야 한다. 이후 클라이언트용 컴포넌트에서 자주 쓰게 될 패턴이다.

data-* 변형과 not-

Base UI는 상태를 data-* 속성으로 알려 준다. Button은 비활성일 때 data-disabled를 붙인다. Tailwind의 data-disabled:는 그 속성이 있을 때만 적용된다. 

/* hover:not-data-disabled:bg-primary-hover */
@media (hover: hover) {
  .hover\:not-data-disabled\:bg-primary-hover:hover:not([data-disabled]) { ... }
}

/* data-disabled:not-data-loading:bg-surface-muted */
.data-disabled\:not-data-loading\:bg-surface-muted[data-disabled]:not([data-loading]) { ... }
  • 변형은 왼쪽부터 이어 붙는다. hover:not-data-disabled:는 "마우스가 올라가 있고 비활성이 아닐 때"다. hover:는 @media (hover: hover)로 감싸져서, 터치 화면에서 탭한 뒤 hover 색이 남지 않는다.
  • not-은 조건을 뒤집는다. 같은 우선순위의 규칙 두 개(hover:bg-primary-hover와 data-disabled:bg-surface-muted)가 부딪히면 CSS에서 뒤에 오는 규칙이 이기는데, 그 순서는 Tailwind가 정한다. not-으로 두 조건이 동시에 참이 되지 않게 하면 순서에 기대지 않아도 된다.
  • 로딩 중에는 Base UI에 disabled를 넘기므로 data-disabled도 붙는다. 비활성 회색을 data-disabled:not-data-loading:에만 걸어서, 로딩 중에는 원래 종류의 색을 유지한다.
  • React에서 data-loading={isLoading || undefined}로 쓰는 이유가 있다. false를 넘기면 data-loading="false"라는 속성이 그대로 남아 [data-loading] 선택자에 걸린다. undefined여야 속성이 사라진다.

motion-safe: 움직임 줄이기

@media (prefers-reduced-motion: no-preference) {
  .motion-safe\:animate-loading-dot { animation: var(--animate-loading-dot); }
}
  • prefers-reduced-motion은 OS의 접근성 설정을 브라우저가 알려 주는 미디어 쿼리다. macOS에서는 시스템 설정 > 손쉬운 사용 > 디스플레이 > "동작 줄이기"다.
  • motion-safe:는 이 설정이 꺼져 있을 때(no-preference)만 적용된다. 반대로 motion-reduce:는 켜져 있을 때만 적용된다.
  • 움직이는 화면은 전정기관 장애나 편두통이 있는 사람에게 어지러움을 일으킬 수 있다(WCAG 2.3.3). 설정을 켠 사람에게 Button의 점은 멈춘 채로 보이고, 로딩 중이라는 사실은 점과 aria-busy로 계속 전달된다.
  • Skeleton도 motion-safe:animate-pulse로 같은 규칙을 따른다.

Chrome DevTools에서 ⌘⇧P를 누르고 "Emulate CSS prefers-reduced-motion: reduce"를 고르면 설정을 바꾸지 않고 확인할 수 있다.

애니메이션 토큰과 임의 속성

/* packages/store-ui/src/tokens.css */
@theme {
  --animate-loading-dot: loading-dot 1s ease-in-out infinite;

  @keyframes loading-dot {
    0%, 80%, 100% { opacity: 0.4; transform: scale(0.7); }
    40%           { opacity: 1;   transform: scale(1); }
  }
}
  • --animate-* 변수가 animate-* 클래스를 만든다. @keyframes를 같은 @theme 안에 두면 그 클래스를 실제로 쓸 때만 키프레임이 CSS에 나온다. 항상 내보내야 하는 키프레임만 @theme 밖에 둔다.
  • @theme 안에 중첩 블록이 생기면서 토큰 문서 파서도 고쳤다. 첫 }에서 자르던 방식을 중괄호 깊이를 세는 방식으로 바꿨다(008 문서).
  • 점 세 개는 같은 애니메이션을 쓰고 시작만 늦춘다. Tailwind에 animation-delay 전용 클래스가 없어서 [animation-delay:160ms]처럼 CSS 속성을 대괄호 안에 그대로 쓰는 임의 속성 문법을 쓴다.
  • bg-current는 background-color: currentColor다. 점이 버튼 글자색을 따라가서, 주요 버튼에서는 흰 점, 보조 버튼에서는 진한 회색 점이 된다.
  • rounded-full은 tokens.css에서 모서리 토큰을 지웠어도 생성된다. 테마 변수가 아니라 고정값(아주 큰 px)으로 만들기 때문이다. 반면 inset-0은 --spacing에 기대므로 생성되지 않는다. 어떤 클래스가 토큰에 기대는지 헷갈리면 생성된 CSS를 확인한다.

우리 프로젝트에서는

  • Button의 상태 스타일은 모두 data-* 속성으로 건다. Base UI가 붙이는 속성을 그대로 쓰므로, focusableWhenDisabled로 native disabled 대신 aria-disabled가 붙는 경우에도 같은 모습이 된다.
  • 로딩 표시는 처음에 한쪽이 빈 원(border 스피너)이었다. 예매·금융 앱 버튼에서 흔하고 부드러운 방향(A)에 어울리는 점 세 개로 바꿨다.
  • tokens.css가 Tailwind 기본 간격을 지웠기 때문에, 숫자 간격 클래스는 0이라도 쓸 수 없다. README의 store-ui 절에 적어 두었다.

스스로 확인하기

1. 버튼에서 relative를 빼면 로딩 점은 어디에 그려지나?

오버레이가 position이 지정된 가장 가까운 바깥 조상을 기준으로 inset: 0을 적용한다. 그 조상 전체를 덮는 상자가 되어 점이 그 조상의 가운데에 나타난다. 그런 조상이 없으면 첫 화면 크기의 상자를 기준으로 삼는다.

2. 라벨을 opacity-0 대신 invisible로 숨기면 무엇이 달라지나?

폭은 똑같이 유지된다. 하지만 visibility: hidden인 요소는 접근성 트리에서도 빠져서, 로딩 중에는 버튼의 이름이 없어진다. 스크린 리더가 "버튼"이라고만 읽는다.

3. data-disabled:bg-surface-muted에서 not-data-loading을 빼면 로딩 중인 주요 버튼은 어떤 색이 되나?

회색이 된다. 로딩 중에도 Base UI에 disabled를 넘기므로 data-disabled가 붙기 때문이다. 로딩과 비활성이 같은 모습이 되어, 사용자는 기다리면 되는지 누를 수 없는 상태인지 구분할 수 없다.

4. 카드 안에 버튼이 있고 둘 다 group이면 버튼 안의 group-hover: 는 언제 적용되나?

카드에 마우스를 올리기만 해도 적용된다. group-hover:는 가장 가까운 group이 아니라 group인 조상 중 하나라도 hover이면 걸린다. 버튼에만 반응하게 하려면 group/button과 group-hover/button:처럼 이름을 붙인다.
