01 반복 쿼리를 배열로 받기: preprocess, array, enum

GET /shows?genre=musical&genre=play처럼 같은 이름을 여러 번 보내는 쿼리를 apps/api/src/shows/show-list-query.ts가 어떻게 받는지 설명한다. 쿼리 문자열이 어떤 값으로 들어오고, z.preprocess, z.array, z.enum, .default가 그 값을 차례로 어떻게 바꾸고 검사하는지 실제 값으로 따라간다. 표의 값은 모두 저장소의 스키마와 Express 5.3.0의 쿼리 파서로 직접 실행해 얻었다. zod의 기본 문법(parse, 체이닝, default, meta)은 zod 00 문서에 있다.

한눈에 보기

같은 이름이 한 번이면 글자, 여러 번이면 배열로 들어온다. 그래서 검사하기 전에 preprocess로 늘 배열로 맞추고, array가 배열인지, enum이 항목마다 정해진 값인지 본다. 값이 아예 없으면 바깥의 default가 먼저 []를 돌려준다. 

genre: z
  .preprocess(wrapInArray, z.array(z.enum(GENRES, GENRE_MESSAGE)))
  .default([])
  .meta({ description: '장르. 여러 번 보내면 그중 하나에 맞는 공연을 고른다(OR). ...' }),
값이 지나가는 순서 (바깥에서 안쪽으로)
  1. .default([]): 값이 없으면 []로 끝
  2. wrapInArray: 글자를 배열로
  3. z.array: 배열인지
  4. z.enum: 항목마다 정해진 값인지

status도 모양이 같고, 고를 수 있는 값만 SHOW_LIST_SALES_STATUSES(on_sale, upcoming)로 다르다. 그래서 이 문서는 genre로 설명한다.

쿼리 문자열이 값이 되기까지

zod가 받는 것은 주소의 글자가 아니라, Express가 쿼리 문자열을 풀어 만든 req.query 객체의 값이다. Nest가 쓰는 Express 5는 쿼리 파서 기본값이 'simple'이고, 이것은 Node의 node:querystring의 parse다. 

import { parse } from 'node:querystring';

parse('genre=musical').genre;             // 'musical'             ← 글자
parse('genre=musical&genre=play').genre;  // ['musical', 'play']   ← 배열
parse('').genre;                          // undefined             ← 키가 없다
parse('genre=').genre;                    // ''                    ← 빈 글자
주소 req.query.genre 타입
/showsundefined없음
/shows?genre=musical'musical'string
/shows?genre=musical&genre=play['musical', 'play']string[]
/shows?genre=''string

같은 필드인데 타입이 둘이다. 장르를 하나 고르면 글자, 둘 이상 고르면 배열이다. 스키마가 둘 중 하나만 받으면 다른 쪽이 400이 된다. 이 문서의 문법은 모두 이 문제를 풀려고 쓴 것이다.

preprocess: 검사 전에 값 바꾸기

z.preprocess(함수, 스키마)는 들어온 값을 먼저 함수에 넣고, 함수가 돌려준 값을 뒤의 스키마로 검사한다. zod는 기본으로 값을 바꾸지 않으므로 (zod 00 문서), 검사 전에 모양을 맞추고 싶을 때 이것을 쓴다. z.coerce가 "글자를 숫자로" 바꾸는 정해진 변환이라면, preprocess는 변환을 직접 함수로 적는 일반형이다. 

// 값이 없을 때는 바깥의 default가 먼저 []를 돌려주므로 이 함수까지 오지 않는다.
function wrapInArray(value: unknown): unknown[] {
  return [value].flat();
}

[value].flat()은 값을 배열 하나로 감싼 뒤, 배열이 겹쳤으면 한 겹 벗긴다.

value [value] .flat()
'musical'['musical']['musical']
['musical', 'play'][['musical', 'play']]['musical', 'play']
''['']['']

글자든 배열이든 결과는 늘 배열이다. .flat()은 한 겹만 벗기지만, 쿼리 파서는 배열 안에 배열을 만들지 않으므로 한 겹이면 된다.

입력 타입은 unknown이 된다

preprocess의 함수는 무엇이든 받으므로, 스키마의 입력 타입(z.input)은 unknown이 된다. 출력 타입(z.output, z.infer)은 뒤의 스키마가 정하므로 Genre[]다. 서비스는 출력 타입만 보므로 genre를 Genre[]로 쓴다. 

type In = z.input<typeof showListQuerySchema>['genre'];   // unknown
type Out = z.output<typeof showListQuerySchema>['genre'];  // ('musical' | 'play' | ... )[]

array: 배열인지, 항목마다 검사

z.array(항목 스키마)는 두 가지를 본다. 값이 배열인지, 그리고 배열의 항목 하나하나가 안쪽 스키마를 통과하는지다. 항목 검사에서 걸리면 오류 위치(path)에 그 항목의 순번이 붙는다.

preprocess 없이 글자를 바로 넣으면 첫 번째 검사에서 걸린다.

const genres = z.array(z.enum(GENRES, GENRE_MESSAGE));

genres.safeParse(['musical']); // 성공: ['musical']
genres.safeParse('musical');   // 실패
{ code: 'invalid_type', path: [], message: 'Invalid input: expected array, received string' }

장르를 하나만 고르는 가장 흔한 요청(?genre=musical)이 400이 되는 셈이다. 그래서 array 앞에 preprocess를 둔다.

enum: 정해진 값 중 하나

z.enum(값 목록, 메시지)는 값이 목록 중 하나인지 본다. GENRES는 DB 스키마의 장르 목록이고, as const로 적혀 있어 글자 하나하나가 타입이 된다. 

// apps/api/src/db/schema/shows.ts
export const GENRES = ['musical', 'play', 'concert', 'classical_dance', 'kids_family'] as const;

// apps/api/src/shows/show-list-query.ts
const GENRE_MESSAGE = `${GENRES.join(', ')} 중 하나여야 합니다.`;
z.enum(GENRES, GENRE_MESSAGE);
  • 메시지: 두 번째 인자는 실패했을 때의 메시지다. 없으면 Invalid option: expected one of ... 같은 zod 기본 영어 메시지가 나간다.
  • 타입 좁히기: 통과한 값의 타입은 string이 아니라 'musical' | 'play' | ...다. 그래서 z.array(z.enum(GENRES))의 결과는 Genre[]이고, DB의 enum 컬럼에 그대로 넘길 수 있다.
  • 오류 위치: array 안의 enum에서 걸리면 path가 ['genre', 순번]이 된다. 검증 파이프가 이것을 genre.1처럼 점으로 이어 Problem Details의 errors[].field에 담는다(nest 05 문서).

default: 바깥에서 먼저 막는다

체이닝은 뒤에 붙인 것이 바깥을 감싼다. z.preprocess(...).default([])는 "default 상자 안에 preprocess 상자"이고, 값은 바깥 상자부터 지나간다.

  • .default([]) undefined면 []를 돌려주고 끝. 아니면 안쪽으로
    • z.preprocess(wrapInArray) 값을 배열로 감싼다
      • z.array 배열이 아니면 실패
        • z.enum(GENRES) 항목마다. 목록에 없으면 실패(path에 순번)

그래서 값이 없으면 wrapInArray는 아예 불리지 않는다. 함수가 undefined를 따로 다루지 않아도 되는 이유다. 함수에 로그를 넣고 default의 자리만 바꿔 실행해 보면 차이가 보인다. 

const wrap = (v: unknown) => { console.log('wrapInArray 호출, 받은 값:', v); return [v].flat(); };
const outer = z.preprocess(wrap, z.array(z.enum(GENRES))).default([]);  // 지금 코드
const inner = z.preprocess(wrap, z.array(z.enum(GENRES)).default([]));  // default를 안쪽에
스키마 넣은 값 wrapInArray 결과
outerundefined불리지 않음[]
outer'musical''musical'을 받음['musical']
innerundefinedundefined를 받음실패 path [0], invalid_value
inner'musical''musical'을 받음['musical']

순서를 바꾸면 달라진다. z.preprocess(wrapInArray, z.array(...).default([]))처럼 default를 안쪽에 두면, undefined가 먼저 [undefined]로 감싸져 default에 닿기 전에 값이 생긴다. 그러면 enum에서 실패한다.

default는 undefined에만 작동한다. ?genre=는 빈 글자 ''가 온 것이라 안쪽으로 들어가 ['']가 되고, enum에서 400이 된다.

빈 배열은 서비스에서 "장르로 거르지 않는다"는 뜻이다(서비스에서 쓰는 곳). optional()로 두어 undefined를 넘기는 대신 []로 맞추면, 서비스가 "없음"과 "빈 배열"을 따로 다루지 않아도 된다.

OpenAPI와 생성 타입에 나가는 모양

이 스키마는 검사에만 쓰이지 않는다. Nest가 같은 스키마로 OpenAPI 문서를 만들고(zod 00 문서), packages/api-client가 그 문서로 스토어의 타입을 만든다. 요청 값의 모양을 문서로 적을 때는 입력 쪽(io: 'input')으로 바꾸고, 이때 preprocess는 뒤의 스키마만 내보낸다. 

// apps/api/openapi.json의 genre 파라미터 schema
{
  "type": "array",
  "items": {
    "type": "string",
    "enum": ["musical", "play", "concert", "classical_dance", "kids_family"]
  }
}
// packages/api-client가 만든 타입
genre?: ("musical" | "play" | "concert" | "classical_dance" | "kids_family")[];

스토어는 이 타입대로 배열을 넘긴다. openapi-fetch는 배열을 같은 이름을 여러 번 쓴 쿼리로 보내고, 빈 배열은 아예 보내지 않는다. 

client.GET('/shows', { params: { query: { genre: ['musical', 'play'], status: [] } } });
// → /shows?genre=musical&genre=play   (status는 빠진다)

z.union을 쓰지 않은 이유

"글자 또는 배열"을 그대로 적는 방법도 있다. 검사는 똑같이 되지만, 문서에도 두 모양이 그대로 나간다.

z.union([z.enum(GENRES), z.array(z.enum(GENRES))]).transform((value) => [value].flat());
{ "anyOf": [
  { "type": "string", "enum": [...] },
  { "type": "array", "items": { "type": "string", "enum": [...] } }
] }

그러면 생성 타입이 Genre | Genre[]가 되어, 스토어가 글자와 배열을 둘 다 고려해야 한다. 글자는 쿼리 파서가 만드는 사정일 뿐 계약이 아니므로, 문서에는 배열 하나만 나가는 preprocess를 골랐다.

값 여섯 개가 지나가는 길

주소마다 req.query.genre, wrapInArray를 지난 값, 최종 결과다.

주소 req.query.genre wrapInArray 뒤 결과
? (없음)undefined불리지 않음[] default
?genre=musical'musical'['musical']['musical']
?genre=musical&genre=play['musical', 'play']그대로['musical', 'play']
?genre=opera'opera'['opera']400 field genre.0
?genre=musical&genre=opera['musical', 'opera']그대로400 field genre.1
?genre=''['']400 field genre.0

400 응답의 본문은 이렇다(apps/api/test/shows.int.spec.ts의 "모르는 값은 400으로 응답한다" 테스트).

{
  "status": 400,
  "code": "VALIDATION_FAILED",
  "errors": [
    { "field": "genre.0", "detail": "musical, play, concert, classical_dance, kids_family 중 하나여야 합니다." }
  ]
}

서비스에서 쓰는 곳

검사를 통과한 값은 늘 Genre[]이므로, 서비스는 길이만 보고 조건을 붙인다. 비었으면 undefined를 넘겨 and가 그 조건을 건너뛴다(db-and-drizzle 03 문서). 

// apps/api/src/shows/shows.service.ts
const listCondition = and(
  ne(salesStatus.salesStatus, 'ended'),
  q ? ilike(shows.title, `%${escapeLikePattern(q)}%`) : undefined,
  // 고른 값이 없으면 거르지 않는다. 같은 이름 안의 값은 OR(IN), 다른 조건과는 AND다.
  genre.length > 0 ? inArray(shows.genre, genre) : undefined,
  status.length > 0 ? inArray(salesStatus.salesStatus, status) : undefined,
);
-- ?genre=musical&genre=concert&status=upcoming
WHERE sales_status <> 'ended'
  AND shows.genre IN ('musical', 'concert')   -- 같은 이름 안은 OR
  AND sales_status IN ('upcoming')            -- 장르와 판매 상태 사이는 AND

스토어의 정리와 다른 점

스토어도 주소의 genre를 읽지만 규칙이 다르다. API는 계약을 지키지 않은 요청을 거절하고, 스토어는 사람이 고친 주소를 고쳐 준다.

들어온 값 API (zod 스키마) 스토어 (parseChoices)
genre=opera400버리고 정리된 주소로 리다이렉트
genre=musical&genre=musical그대로 통과. IN은 겹쳐도 결과가 같다하나로 줄인다
genre=concert&genre=musical그대로 통과장르 목록 순서(musical, concert)로 맞춘다

스토어가 겹침과 순서까지 맞추는 것은 같은 조건이 늘 같은 주소가 되게 하려는 것이다. 스토어는 정리한 값만 API에 보내므로, 스토어를 거친 요청은 API에서 400을 받지 않는다. 스토어 쪽 함수는 store-logic 00 문서에 있다.

헷갈리기 쉬운 점

쉼표로 이은 값은 하나의 글자다. ?genre=musical,play는 'musical,play' 글자 하나로 들어와 ['musical,play']가 되고 genre.0에서 400이 된다. 이 API는 같은 이름을 여러 번 쓰는 방식만 받는다.

default는 바깥에 둔다. 체이닝은 뒤에 붙인 것이 바깥이다. 안쪽에 두면 undefined가 먼저 감싸져 기본값이 작동하지 않는다(default 절).

빈 글자는 "없음"이 아니다. ?genre=는 ''가 온 것이라 기본값이 아니라 400이다.

입력 타입은 unknown이다. preprocess를 쓰면 z.input이 unknown이 된다. 타입으로 요청 모양을 알고 싶으면 z.infer(출력)나 OpenAPI 문서를 본다.

스스로 확인하기

1. preprocess를 빼면 아래 세 요청은 각각 어떻게 되는가?

쿼리 문자열이 값이 되기까지와 array 절을 묻는다.

-  genre: z
-    .preprocess(wrapInArray, z.array(z.enum(GENRES, GENRE_MESSAGE)))
+  genre: z
+    .array(z.enum(GENRES, GENRE_MESSAGE))
     .default([])
요청
/shows
/shows?genre=musical
/shows?genre=musical&genre=play
답 보기
  • /shows: 값이 없어 default가 []를 돌려준다. 성공.
  • /shows?genre=musical: 글자 'musical'이 array에 바로 가서 expected array, received string으로 400이다. 장르 하나만 고르는 요청이 실패한다.
  • /shows?genre=musical&genre=play: 배열이 오므로 성공. 둘 이상 고를 때만 되는 이상한 API가 된다.

2. 아래처럼 고치면 /shows(genre 없음)는 어떻게 되는가?

default 절의 감싸는 순서를 묻는다. wrapInArray는 지금처럼 [value].flat()이다.

   genre: z
-    .preprocess(wrapInArray, z.array(z.enum(GENRES, GENRE_MESSAGE)))
-    .default([])
+    .preprocess(wrapInArray, z.array(z.enum(GENRES, GENRE_MESSAGE)).default([]))
답 보기

400이다. 이제 바깥에 preprocess가 있어 undefined가 먼저 wrapInArray에 들어가 [undefined]가 된다. 값이 있으므로 안쪽의 default는 작동하지 않고, enum이 undefined를 거절해 genre.0에서 실패한다. 이 순서로 쓰려면 wrapInArray가 undefined를 감싸지 않고 그대로 넘겨야 한다.

3. 스토어 사용자가 장르 칩을 하나도 고르지 않았을 때, API 요청 주소와 서비스의 SQL 조건은 무엇인가?

OpenAPI와 생성 타입, 서비스에서 쓰는 곳 절을 묻는다. 스토어는 genre: []를 넘긴다.

답 보기

openapi-fetch가 빈 배열을 보내지 않으므로 주소에 genre가 없다. API에서는 default가 []를 돌려주고, 서비스는 genre.length > 0이 거짓이라 undefined를 넘긴다. and가 그 조건을 건너뛰어 SQL에 장르 조건이 붙지 않는다.
