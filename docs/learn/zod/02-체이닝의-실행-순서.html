02 체이닝의 실행 순서: 이어 붙이기와 문지기

zod 체이닝은 왼쪽부터 차례로 실행될 것처럼 읽히지만, .default(), .optional() 같은 몇 메서드는 맨 뒤에 써도 가장 먼저 값을 본다. 스키마를 만들 때와 값을 검사할 때의 순서가 왜 다른지 화살표 함수로 풀고, 메서드마다 어느 쪽인지 정리한다. 예제의 결과는 모두 저장소의 zod 4.6.7로 실행해 확인했다. 체이닝이 새 스키마를 돌려준다는 기본은 zod 00 문서에 있다.

한눈에 보기

메서드는 두 종류가 섞여 있다. 이어 붙이기는 앞 단계 결과를 받아 다음 일을 하므로 쓴 순서대로 실행된다. 문지기는 앞의 스키마 전체를 감싸고 안쪽을 부르기 전에 값을 먼저 확인하므로, 어디에 쓰든 가장 먼저 실행된다.

종류 메서드 실행 순서
이어 붙이기.transform, .refine, .pipe, .min/.max/.int 같은 검사쓴 순서대로
문지기.default, .optional, .nullable어디에 쓰든 가장 먼저 값을 본다
감싸지만 나중.catch안쪽을 먼저 해 보고, 실패하면 대신 값을 돌려준다
함수로 감싸기z.preprocess(fn, schema)fn이 schema보다 먼저
 
z.coerce.number().int().min(1).default(1)
// 쓴 순서:   coerce → int → min → default
// 실행 순서: default → coerce → int → min   (값이 undefined면 default에서 끝)

만들 때와 검사할 때

체이닝 코드는 두 번 다른 일을 한다. 서버가 켜질 때 한 번 스키마를 만들고, 요청이 올 때마다 값을 검사한다. 두 시점의 순서가 반대라서 헷갈린다. 함수에 로그를 넣어 두 시점을 나눠 보면 이렇다. 

const wrapInArray = (v: unknown) => { console.log('[검사] wrapInArray 실행:', v); return [v].flat(); };

console.log('① 스키마 만들기 시작');
const arr = z.array(z.enum(['musical', 'play']));
const pre = z.preprocess(wrapInArray, arr);   // wrapInArray는 아직 실행 안 됨
const schema = pre.default([]);

console.log('② 검사');
schema.safeParse(undefined);
schema.safeParse('musical');
① 스키마 만들기 시작
② 검사
[검사] wrapInArray 실행: musical
  • 만들 때는 자바스크립트 규칙대로 인자부터 실행된다. z.array(...)가 먼저 만들어지고, 그것을 받아 z.preprocess(...), 그것을 받아 .default([])가 만들어진다. 이때 wrapInArray는 괄호 없이 함수 자체로 넘겨져 맡겨 둘 뿐, 실행되지 않는다.
  • 검사할 때는 손에 쥔 schema, 즉 마지막에 만든 것부터 실행된다. undefined는 default에서 끝나 wrapInArray가 한 번도 불리지 않았고, 'musical'일 때만 불렸다.

(안쪽) => (값) => 결과

스키마를 만드는 메서드와 함수는 모두 화살표가 두 번인 함수로 흉내 낼 수 있다.

const makeDefault = (inner, defaultValue) => (value) =>
  value === undefined ? defaultValue : inner(value);

const makePreprocess = (fn, inner) => (value) =>
  inner(fn(value));

const makeArray = (element) => (value) =>
  Array.isArray(value) ? value.map(element) : fail('배열이 아니다');

const makeEnum = (allowed) => (value) =>
  allowed.includes(value) ? value : fail('목록에 없다');
  • 바깥 화살표 (inner, ...) =>: 만들 때 실행된다. 안쪽 담당자를 받아 안쪽 화살표 함수를 돌려주기만 한다.
  • 안쪽 화살표 (value) =>: 검사할 때 실행된다. 값을 보고, 필요할 때만 inner(value)를 부른다.
// z.preprocess(wrapInArray, z.array(z.enum(GENRES))).default([]) 와 같다
const schema = makeDefault(makePreprocess(wrapInArray, makeArray(makeEnum(GENRES))), []);

schema(undefined); // []: makeDefault의 안쪽 화살표가 inner를 부르지 않고 끝낸다

각 함수에 로그를 넣어 실행하면 zod와 같은 순서가 찍힌다.

schema(undefined)
    default 검사: undefined
    결과: []
schema("musical")
    default 검사: "musical"
    wrapInArray: "musical" → ["musical"]
    array 검사: ["musical"]
    enum 검사: "musical"
    결과: ["musical"]

최종 함수: 함수 안에 함수

make...가 실행될 때마다 앞에서 만든 함수가 새 함수의 inner(...) 자리에 들어간다. 그래서 schema에 최종적으로 든 함수는 양파처럼 겹친 모양이다. 중간 변수 없이 그대로 쓰면 이렇다. 

const schema = (value) => {
  if (value === undefined) return [];        // default

  return ((value) => {                       // preprocess
    return ((value) => {                     // array
      if (!Array.isArray(value)) fail('배열이 아니다');
      return value.map((item) => {           // enum
        if (!GENRES.includes(item)) fail('목록에 없다');
        return item;
      });
    })([value].flat());                      // ← wrapInArray 결과를 array 함수에 넘긴다
  })(value);                                 // ← 값을 preprocess 함수에 넘긴다
};
  • default 함수 가장 마지막에 만들었고, 가장 바깥이다. 값을 가장 먼저 받는다
    • preprocess 함수 default가 부를 때만 실행된다
      • array 함수 preprocess가 부를 때만
        • enum 함수 가장 먼저 만들었고, 가장 안쪽이다

schema(undefined)는 첫 줄 return []에서 끝나므로 안쪽 함수들은 불리지 않는다. 만든 순서는 안쪽부터, 실행 순서는 바깥부터다. 러시아 인형을 만들 때는 작은 인형부터 만들어야 큰 인형에 넣을 수 있고, 열 때는 큰 인형부터 여는 것과 같다.

문지기를 안쪽에 두면

z.preprocess(wrapInArray, z.array(...).default([]))처럼 default를 배열에 붙이면, default가 preprocess보다 먼저 만들어져 최종 함수의 안쪽으로 들어간다. 

const schemaC = (value) => {
  return ((value) => {                       // default (이제 안쪽)
    if (value === undefined) return [];
    return ((value) => {                     // array
      if (!Array.isArray(value)) fail('배열이 아니다');
      return value.map((item) => {           // enum
        if (!GENRES.includes(item)) fail('목록에 없다');
        return item;
      });
    })(value);
  })([value].flat());                        // ← preprocess: 먼저 감싸서 넘긴다
};

schemaC(undefined); // 실패: [undefined]는 undefined가 아니라 default를 지나치고, enum이 undefined를 거절한다

zod 객체와 소스에서 확인하기

위 모델이 실제 zod와 같은지 확인한다. 메서드를 붙이면 앞의 스키마를 품은 새 객체가 생긴다(zod 00 문서). 

const a = z.array(z.enum(['x']));
const b = a.default([]);

a === b;                     // false: 새 객체다
b._zod.def.innerType === a;  // true: 새 객체 안에 a가 들어 있다

z.preprocess(wrapInArray, z.array(z.enum(GENRES))).default([])를 만들고 _zod.def를 따라가면 객체가 이렇게 겹쳐 있다. z.preprocess는 따로 있는 종류가 아니라 pipe 하나다. 

default { innerType, defaultValue: [] }
└ pipe { in, out }
  ├ in:  transform { transform: wrapInArray }
  └ out: array { element }
         └ enum { entries: GENRES }

검사할 때 각 객체가 안쪽을 부를지 정하는 코드다. v4/core/schemas.js를 줄여 옮겼다.

// $ZodDefault
inst._zod.parse = (payload, ctx) => {
  if (payload.value === undefined) {
    payload.value = def.defaultValue; // 기본값을 넣고
    return payload;                   // 바로 돌아간다. 안쪽(innerType)을 부르지 않는다
  }
  return def.innerType._zod.run(payload, ctx); // 값이 있을 때만 안쪽을 부른다
};

// $ZodPipe
inst._zod.parse = (payload, ctx) => {
  const left = def.in._zod.run(payload, ctx);  // 먼저 왼쪽
  return handlePipeResult(left, def.out, ctx); // 그 결과로 오른쪽. 실패했으면 멈춘다
};

makeDefault, makePreprocess와 하는 일이 같다.

이어 붙이기: 쓴 순서대로

.transform, .refine, .pipe는 앞 단계를 왼쪽에 두고 자기를 오른쪽에 두는 pipe를 만든다. pipe는 왼쪽부터 실행하므로 쓴 순서와 실행 순서가 같다. .min, .int 같은 검사도 앞 스키마에 검사를 하나씩 더하는 것이라 쓴 순서대로 실행된다. 

z.string()
  .transform((v) => v + '!')  // 1번째
  .refine((v) => true)        // 2번째
  .transform((v) => v);       // 3번째
// 실행: transform1 → refine → transform2

문지기: 어디에 쓰든 먼저

.default, .optional, .nullable은 앞의 스키마 전체를 innerType으로 감싸고, 안쪽을 부르기 전에 값이 비었는지 확인한다. 비었으면 안쪽을 부르지 않는다.

메서드 먼저 확인하는 것 맞으면
.default(v)undefined인가v를 돌려주고 끝
.optional()undefined인가undefined를 돌려주고 끝
.nullable()null인가null을 돌려주고 끝
 
const trimmed = z.string().transform((v) => v.trim());

trimmed.optional().parse(undefined);  // undefined (transform 안 불림)
trimmed.nullable().parse(null);       // null      (transform 안 불림)
trimmed.default('기본').parse(undefined); // '기본'  (transform 안 불림)

zod 00 문서의 z.coerce.number().int().min(1).default(1)이 쿼리를 생략한 요청에 1을 주는 것도 이 덕분이다. default가 없으면 undefined가 coerce로 가서 NaN이 되고 실패한다.

문지기는 자기가 감싼 것만 지킨다. 이어 붙이기 메서드를 문지기 뒤에 쓰면, 그 단계는 문지기 바깥(pipe의 오른쪽)에 놓여 문지기가 돌려준 값을 그대로 받는다. 스스로 확인하기 1번이 이 경우다.

prefault: 기본값도 검사를 거치게 하려면

.default(v)는 기본값을 검사하지 않고 그대로 돌려준다. 기본값을 넣은 뒤 안쪽 검사까지 거치게 하려면 .prefault(v)를 쓴다. 예를 들어 z.string().min(3).prefault('ab').safeParse(undefined)는 'ab'가 min(3)에 걸려 실패한다.

catch: 안쪽을 먼저 해 보고

.catch(v)도 앞의 스키마를 감싸지만, 문지기와 반대로 안쪽을 먼저 실행한다. 실패했을 때만 v를 돌려준다. 

z.string().min(3).catch('기본').parse('ab');  // '기본' (min(3)을 해 보고 실패해서)
z.string().min(3).catch('기본').parse('abc'); // 'abc'

함수로 감싸기: z.preprocess

z.preprocess(fn, schema)는 메서드가 아니라 스키마를 인자로 받는 함수다. 인자가 안쪽이 되므로 fn이 schema보다 먼저 실행된다. 한 줄에 함수로 감싸기와 메서드로 감싸기가 섞이면 순서를 읽기 어려워진다. 

z.preprocess(wrapInArray, z.array(z.enum(GENRES)))  // 함수: 안쪽 스키마를 인자로 감싼다
  .default([])                                       // 메서드: 그 결과를 또 감싼다
// 실행: default → wrapInArray → array → enum

.default에도 함수형 z._default(안쪽, 기본값)이 있다(default가 예약어라 밑줄이 붙었다). 바깥을 먼저 쓰므로 읽는 순서와 실행 순서가 맞지만, 문서와 예제에서 거의 쓰지 않아 이 저장소는 메서드를 쓴다. 

z._default(z.preprocess(wrapInArray, z.array(z.enum(GENRES))), []);
// 구조는 위와 같다: default(pipe(transform, array))

읽는 요령

  1. 문지기부터 찾는다. .default, .optional, .nullable이 있으면 "값이 비었으면 여기서 끝"을 맨 앞에 둔다.
  2. z.preprocess(fn, ...)의 fn을 그다음에 둔다. 인자로 받은 스키마보다 먼저 실행된다.
  3. 나머지는 쓴 순서대로 읽는다. 타입 검사, .min/.int, .transform, .refine.
  4. 문지기 뒤에 이어 붙인 것이 있는지 본다. 있으면 그 단계는 문지기가 돌려준 빈 값도 받는다.

이 저장소의 GET /shows 쿼리 스키마를 이 요령으로 읽은 결과는 zod 01 문서에 있다.

헷갈리기 쉬운 점

"인자부터 실행"은 만들 때의 이야기다. 만들 때 실행되는 것은 스키마를 조립하는 코드뿐이다. 넘긴 함수(wrapInArray, transform의 콜백)는 검사할 때 실행된다.

transform 안의 예외는 safeParse도 잡지 않는다. 콜백이 던진 오류는 검사 실패(success: false)가 아니라 그대로 던져진다. 문지기 뒤의 transform이 빈 값을 받아 .length를 읽으면 요청 처리 전체가 예외로 끝난다.

스스로 확인하기

1. 두 스키마에 undefined를 넣으면 각각 어떻게 되는가?

문지기 절의 경고, 이어 붙이기 절을 묻는다.

const a = z.string().transform((s) => s.length).optional();
const b = z.string().optional().transform((s) => s.length);
답 보기
  • a: undefined. optional이 가장 바깥이라 transform을 부르지 않고 끝낸다.
  • b: 예외가 던져진다(Cannot read properties of undefined (reading 'length')). 구조가 pipe(optional(string), transform)이라 optional은 pipe의 왼쪽에 갇혀 있다. optional이 돌려준 undefined를 오른쪽 transform이 받는다. safeParse로 불러도 실패 결과가 아니라 예외다.

2. 아래 스키마를 검사할 때의 실행 순서를 적어라. 값이 undefined일 때와 '7'일 때 각각 어디까지 실행되는가?

읽는 요령을 묻는다.

z.coerce.number().int().min(1).default(1)
답 보기

실행 순서는 default → coerce → number → int → min이다. undefined는 default에서 1을 돌려주고 끝난다. '7'은 default를 지나 coerce가 7로 바꾸고, number, int, min을 모두 통과해 7이 된다.

3. makeDefault를 아래처럼 고치면 schema(undefined)의 결과와 실행 순서는 어떻게 바뀌는가?

(안쪽) => (값) => 결과 절을 묻는다. schema는 그 절과 같이 만든다.

-const makeDefault = (inner, defaultValue) => (value) =>
-  value === undefined ? defaultValue : inner(value);
+const makeDefault = (inner, defaultValue) => (value) =>
+  inner(value === undefined ? defaultValue : value);
답 보기

기본값 []가 안쪽으로 넘어가 wrapInArray([]) → [] → array 통과 → 항목이 없어 enum은 불리지 않고 []가 나온다. 결과는 같지만 안쪽 검사를 모두 거친다. 이것이 .prefault의 동작이다.
