10 장르·판매 상태 필터 쿼리 읽기

GET /shows?genre=musical&genre=play&status=on_sale이 고른 장르와 판매 상태의 공연만 돌려주는 과정을 따라간다. 중심은 findPage()(apps/api/src/shows/shows.service.ts)의 inArray 두 줄이다. IN 개념은 db-and-drizzle 01 문서, inArray와 and 문법은 db-and-drizzle 03 문서, 반복 쿼리를 배열로 받는 스키마는 zod 01 문서에 있다.

한눈에 보기

고른 필터가 SQL이 되기까지
  1. 주소의 genre=musical&genre=play
  2. zod 스키마가 값을 배열로 맞추고 고를 수 있는 값인지 검사한다 → ['musical', 'play']
  3. 배열이 비지 않았으면 inArray로 IN 조건을 만든다
  4. and()가 판매 종료 제외, 검색어, 장르, 판매 상태 조건을 잇는다
  5. 목록 쿼리와 개수 쿼리의 where에 함께 넣는다
// apps/api/src/shows/shows.service.ts
async findPage({ page, size, sort, q, genre, status }: ShowListQuery): Promise<ShowPageDto> {
  ...
  const listCondition = and(
    ne(salesStatus.salesStatus, 'ended'),
    q ? ilike(shows.title, `%${escapeLikePattern(q)}%`) : undefined,
    // 고른 값이 없으면 거르지 않는다. 같은 이름 안의 값은 OR(IN), 다른 조건과는 AND다.
    genre.length > 0 ? inArray(shows.genre, genre) : undefined,
    status.length > 0 ? inArray(salesStatus.salesStatus, status) : undefined,
  );
  ...
}

서비스가 받는 genre와 status는 늘 배열이다. 쿼리 스키마(apps/api/src/shows/show-list-query.ts)가 한 번 보낸 값도 배열로 감싸고, 보내지 않으면 []를 넣는다.

요청서비스가 받은 genre
/shows[]
/shows?genre=musical['musical']
/shows?genre=musical&genre=play['musical', 'play']
/shows?genre=opera서비스까지 오지 않고 400으로 응답한다

inArray가 만드는 조건

inArray(shows.genre, ['musical', 'play']);
// "shows"."genre" in ($1, $2), params: ['musical', 'play']

"공연의 장르가 musical이거나 play다"라는 뜻이다. IN은 같은 컬럼의 =를 OR로 이은 것과 같다(IN). 

"shows"."genre" in ('musical', 'play')
-- 같은 뜻
"shows"."genre" = 'musical' or "shows"."genre" = 'play'
// 자바스크립트로 치면
shows.filter((show) => ['musical', 'play'].includes(show.genre));

배열의 값은 SQL에 이어 붙지 않고 파라미터로 간다. 값의 타입도 검사하므로 Genre에 없는 글자를 넘기면 컴파일 오류다. 스키마가 이미 값을 Genre[]로 좁혀 두었기 때문에 서비스는 그대로 넘긴다.

빈 배열이면 조건을 뺀다

필터를 하나도 고르지 않은 요청(/shows)은 "장르로 거르지 않는다"여야 한다. 그런데 빈 배열을 inArray에 그대로 넘기면 반대가 된다.

코드genre = []일 때 where 절결과
inArray(shows.genre, genre) (sales_status <> 'ended' and false) 0건
genre.length > 0 ? inArray(...) : undefined sales_status <> 'ended' 판매 종료가 아닌 공연 모두

빈 목록에는 어떤 값도 들어 있지 않으므로 Drizzle은 빈 배열을 false로 바꾼다(빈 배열을 넘기면). and 안에 false가 있으면 모든 행이 빠진다. 그래서 길이를 먼저 보고, 비었으면 undefined를 넘겨 and가 그 조건을 건너뛰게 한다(and와 있을 수도 없을 수도 있는 조건). 검색어 q ? ilike(...) : undefined와 같은 모양이다.

[]는 자바스크립트에서 참(truthy)이다. genre ? inArray(...) : undefined로 쓰면 빈 배열도 조건이 붙어 0건이 된다. 그래서 q ?처럼 쓰지 않고 genre.length > 0을 본다.

같은 이름은 OR, 다른 조건은 AND

주석의 "같은 이름 안의 값은 OR(IN), 다른 조건과는 AND다"는 이렇게 읽는다.

  • 같은 이름 안은 OR. genre=musical&genre=play는 "뮤지컬이거나 연극"이다. 한 inArray의 배열에 들어간다.
  • 다른 조건과는 AND. 장르, 판매 상태, 검색어, 판매 종료 제외는 and()로 이어지므로 모두 맞아야 한다.
-- /shows?genre=musical&genre=concert&status=upcoming
where sales_status <> 'ended'
  and shows.genre in ('musical', 'concert')   -- 뮤지컬이거나 콘서트이면서
  and sales_status in ('upcoming')            -- 판매 예정인 공연

그래서 같은 묶음(장르)에서 여러 개를 고르면 결과가 넓어지고, 다른 묶음(판매 상태)을 더 고르면 결과가 좁아진다. 같은 이름 안을 AND로 묶으면 "뮤지컬이면서 연극인 공연"이라 공연 하나에 장르가 하나뿐인 이 모델에서는 늘 0건이 된다.

listCondition 하나를 목록 쿼리와 개수 쿼리에 함께 넘기므로, 필터를 고르면 목록과 전체 개수(totalCount)가 같이 줄어든다. 이유는 db-and-drizzle 09 문서의 검색어 조건과 같다.

판매 상태는 서브쿼리 필드로 거른다

장르는 shows 테이블의 컬럼이지만, 공연 판매 상태는 저장하지 않고 회차에서 계산한다. showSalesStatusSubquery가 공연마다 판매 상태를 계산하는 서브쿼리를 만들고, 목록 쿼리는 그것을 JOIN한다(db-and-drizzle 06 문서). 

inArray(salesStatus.salesStatus, status);
// "sales_status" in ($1), params: ['on_sale']

salesStatus.salesStatus는 서브쿼리가 .as('sales_status')로 이름 붙인 필드다. inArray의 첫 인자에는 테이블 컬럼뿐 아니라 이런 필드도 넣을 수 있다. ne(salesStatus.salesStatus, 'ended')가 같은 필드를 쓰는 것과 같다.

고를 수 있는 판매 상태는 on_sale, upcoming 둘뿐이다. 판매 종료 공연은 ne(..., 'ended')가 늘 빼므로 목록에 없고, 그래서 선택지도 아니다. status=ended를 보내면 스키마가 400으로 응답한다.

스스로 확인하기

1. 길이 검사를 지우면 어떤 요청의 결과가 바뀌고, 무엇이 나오는가?

빈 배열이면 조건을 뺀다. 장르 줄만 바꾼다.

-  genre.length > 0 ? inArray(shows.genre, genre) : undefined,
+  inArray(shows.genre, genre),
답 보기

장르를 고르지 않은 모든 요청(/shows, /shows?status=on_sale, /shows?q=정원 등)이 바뀐다. genre가 []라서 inArray가 false를 만들고, and 전체가 거짓이 되어 목록이 비고 totalCount가 0이 된다. 장르를 고른 요청은 그대로다.

2. 아래 요청에서 나오는 공연은 무엇인가?

같은 이름은 OR, 다른 조건은 AND. 데이터는 테스트가 확인하는 것의 네 공연이다.

/shows?genre=play&genre=concert&status=on_sale
답 보기

"연극이거나 콘서트"이면서 "판매 중"인 공연이다. 연극 판매 중은 둘 다 맞고, 콘서트 판매 예정은 판매 상태가 맞지 않는다. 결과는 연극 판매 중 하나, totalCount는 1이다.

3. 길이 검사를 아래처럼 바꾸면 무엇이 틀리는가?

빈 배열이면 조건을 뺀다의 강조 상자.

-  genre.length > 0 ? inArray(shows.genre, genre) : undefined,
+  genre ? inArray(shows.genre, genre) : undefined,
답 보기

빈 배열 []도 참이라 늘 inArray가 붙는다. 1번과 같이 장르를 고르지 않은 요청이 모두 0건이 된다. 검색어의 q ?는 빈 글자 ''가 거짓이라 맞게 동작하지만, 배열은 다르다.

4. 장르 조건을 or()로 따로 만들지 않고 inArray 하나로 쓰는 이유는?

or(eq(shows.genre, 'musical'), eq(shows.genre, 'play'))도 같은 뜻이지만, 고른 개수만큼 eq를 만들어야 한다. inArray는 배열을 그대로 받으므로 고른 값이 몇 개든 한 줄로 끝난다.
