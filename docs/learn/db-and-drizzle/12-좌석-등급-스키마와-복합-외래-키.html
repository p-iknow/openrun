12 좌석 등급 스키마와 복합 외래 키

공연 상세에 등급별 가격을 보여 주려고 만든 좌석 등급(seat_grades)과 좌석 등급 지정(seat_grade_assignments) 테이블을 본다. 특히 "공연 1의 좌석에 공연 2의 등급을 지정하는 일"을 복합 외래 키로 막는 방법과, 그러려고 seat_grades에 의미로는 중복인 unique(id, show_id)를 둔 이유를 따라간다. 복합 외래 키 개념은 db-and-drizzle 01 문서, foreignKey() 문법은 db-and-drizzle 02 문서에 있다.

좌석 등급에 관련된 테이블

좌석(seats)은 공연장에 실제로 있는 자리라서 공연과 상관없이 있다. 등급은 공연마다 정한다. 같은 공연장의 같은 자리라도 뮤지컬에서는 VIP석이고 콘서트에서는 R석일 수 있다. 그래서 "이 공연에서 이 자리는 이 등급"이라는 기록을 따로 둔다. 그 기록이 좌석 등급 지정이다.

venues 공연장
  • id
  • name
sections 구역
  • id
  • venue_id
  • name
seats 좌석
  • id
  • section_id
  • row
  • number
shows 공연
  • id
  • venue_id
  • title
seat_grade_assignments 좌석 등급 지정
  • show_id
  • seat_id
  • seat_grade_id

PRIMARY KEY (show_id, seat_id)

seat_grades 좌석 등급
  • id
  • show_id
  • name
  • price

UNIQUE (show_id, name)
UNIQUE (id, show_id)

회색 선은 외래 키다. 세 갈래 까마귀 발(N) 쪽이 "여러 개", 막대(1) 쪽이 "하나"다. 초록 점선은 두 칸을 묶어 거는 복합 외래 키 (seat_grade_id, show_id) → (id, show_id)다. 상자나 칸에 마우스를 올리면 이어진 선만 보인다.

지정 테이블은 공연과 좌석을 잇는 연결 테이블이다. show_id → shows, seat_id → seats, 그리고 seat_grade_id로 등급을 가리킨다. 등급을 가리키는 방법이 이 문서의 주제다. 

// apps/api/src/db/schema/shows.ts
export const seatGrades = pgTable(
  'seat_grades',
  {
    id: integer().primaryKey().generatedAlwaysAsIdentity(),
    showId: integer('show_id').notNull().references(() => shows.id),
    name: text().notNull(),
    price: integer().notNull(),
  },
  (table) => [
    unique().on(table.showId, table.name),
    unique().on(table.id, table.showId), // ← 이 문서가 설명하는 줄
  ],
);

export const seatGradeAssignments = pgTable(
  'seat_grade_assignments',
  {
    showId: integer('show_id').notNull().references(() => shows.id),
    seatId: integer('seat_id').notNull().references(() => seats.id),
    seatGradeId: integer('seat_grade_id').notNull(),
  },
  (table) => [
    primaryKey({ columns: [table.showId, table.seatId] }),
    foreignKey({
      name: 'seat_grade_assignments_seat_grade_fk',
      columns: [table.seatGradeId, table.showId],
      foreignColumns: [seatGrades.id, seatGrades.showId],
    }),
  ],
);

막고 싶은 행: 다른 공연의 등급

좌석 501에 뮤지컬 A의 등급을 지정하려는데, 실수로 이런 행을 넣는다고 하자.

show_idseat_idseat_grade_id뜻
150120뮤지컬 A에서 이 자리는 스탠딩

등급 20(스탠딩)은 콘서트 B의 등급이다. 이 행이 들어가면 뮤지컬 A의 좌석 화면에 뮤지컬 A가 정한 적 없는 99,000원짜리 스탠딩이 보인다.

외래 키를 seat_grade_id 하나로만 걸면

seatGradeId: integer('seat_grade_id').notNull().references(() => seatGrades.id),

DB는 이것만 검사한다.

"seat_grades에 id가 20인 행이 있나?" → 있다 → 통과

그 등급이 어느 공연의 것인지는 보지 않는다. 지정 행의 show_id는 1이고 등급 20의 show_id는 2인데, 단일 외래 키는 이 두 값을 비교하지 않는다.

해결: 등급과 공연을 묶어 가리키기

외래 키를 두 컬럼 묶음으로 건다.

foreignKey({
  columns:        [table.seatGradeId, table.showId],      // 지정 행에서 꺼낼 두 값
  foreignColumns: [seatGrades.id,     seatGrades.showId], // 등급 테이블에서 찾을 두 컬럼
})
ALTER TABLE "seat_grade_assignments" ADD CONSTRAINT "seat_grade_assignments_seat_grade_fk"
  FOREIGN KEY ("seat_grade_id","show_id") REFERENCES "public"."seat_grades"("id","show_id");

이제 DB는 이렇게 검사한다.

"seat_grades에 id가 seat_grade_id이면서 show_id가 show_id인 행이 있나?"

넣으려는 지정 (show_id, seat_id, seat_grade_id)찾는 등급 (id, show_id)결과
(1, 501, 11)(11, 1)통과 등급 11은 공연 1의 것
(1, 501, 20)(20, 1)거부 등급 20의 show_id는 2라서 (20, 1)인 행이 없다

지정 행의 show_id가 외래 키 검사에 함께 들어가므로, 지정의 공연과 등급의 공연은 늘 같다. API나 시드 코드에 버그가 있어도 DB가 거부한다. 

ERROR:  insert or update on table "seat_grade_assignments" violates foreign key constraint "seat_grade_assignments_seat_grade_fk"
DETAIL:  Key (seat_grade_id, show_id)=(20, 1) is not present in table "seat_grades".

예시를 좌석 501로 든 이유가 있다. 좌석 500에는 공연 1의 지정이 이미 있어서, (1, 500, 20)을 넣으면 외래 키 검사 전에 기본 키 (show_id, seat_id)에서 먼저 실패한다. PostgreSQL은 기본 키·유니크 검사를 행을 넣는 순간에 하고, 외래 키 검사는 그 뒤에 한다.

복합 외래 키는 자동 이름(seat_grade_assignments_seat_grade_id_show_id_seat_grades_id_show_id_fk)이 PostgreSQL 이름 길이 63바이트를 넘어 잘리므로, name으로 직접 지었다.

seat_grades에 unique(id, show_id)를 둔 이유

위 외래 키는 seat_grades의 (id, show_id) 묶음을 가리킨다. PostgreSQL은 외래 키가 가리키는 컬럼 묶음에 그 묶음 그대로의 기본 키나 유니크 제약이 있어야 외래 키를 만든다(이유). 그런데 unique(id, show_id) 없이 seat_grades에 있는 제약은 이것뿐이다.

제약컬럼 묶음외래 키가 가리키는 (id, show_id)와 같나
기본 키(id)아니다. 컬럼 하나
유니크(show_id, name)아니다. 다른 컬럼

그래서 이대로면 마이그레이션이 이렇게 실패한다.

ERROR:  there is no unique constraint matching given keys for referenced table "seat_grades"

이 오류를 없애려고 unique().on(table.id, table.showId)를 더했다.

id가 이미 기본 키라서 (id, show_id)도 당연히 유일하다. 의미로는 중복인 제약이다. PostgreSQL이 이것을 추론해 주지 않으므로, 복합 외래 키를 걸 수 있게 하려고 형식상 두었다. 대가로 인덱스가 하나 더 생긴다. 등급은 공연마다 몇 개뿐이라 비용은 작다.

지정 테이블에 show_id를 둔 이유

지정 테이블에서 show_id를 빼면 이 문제 자체가 없어 보인다. 등급이 이미 공연을 알고 있으니, 공연은 등급을 따라가서 알면 된다. 그래도 show_id를 둔 것은 이 규칙 때문이다.

공연마다 좌석 하나에 등급은 하나뿐이다.

이 규칙은 기본 키 (show_id, seat_id)로 지킨다. 같은 공연에서 좌석 500에 VIP석과 R석을 둘 다 지정하는 행을 DB가 거부한다. show_id가 없으면 이 기본 키를 만들 수 없다. (seat_grade_id, seat_id)로는 막지 못한다. 등급 10과 11이 다른 등급이라서, 두 행의 조합이 다르기 때문이다.

지정 테이블 설계좌석 하나에 등급 하나지정과 등급의 공연이 같음
show_id 없음DB로 못 막음저절로 같음
show_id + 단일 외래 키기본 키로 막음DB로 못 막음
show_id + 복합 외래 키 (지금)기본 키로 막음복합 외래 키로 막음

show_id를 두면 공연이 등급과 지정 두 곳에 적히게 되고, 두 값이 어긋날 수 있다. 복합 외래 키는 그 두 값을 같게 묶어서, 두 규칙을 모두 DB 선언만으로 지킨다. 트리거나 API 검증으로도 막을 수 있지만, 그러면 시드나 직접 실행한 SQL 같은 다른 경로는 막지 못한다.

DB로 막지 않는 규칙

지정 테이블에서 아래 두 규칙은 DB 제약으로 막지 않는다.

  • 좌석이 그 공연의 공연장에 있는가
  • 공연장의 모든 좌석에 등급을 지정했는가

첫째는 좌석에서 구역, 구역에서 공연장으로 두 단계를 따라가야 비교할 수 있어서 외래 키로 표현할 수 없다. 둘째는 "행이 있어야 한다"는 규칙이라 외래 키나 유니크 제약이 다루는 종류가 아니다. 지금은 시드가 지키고, 어드민에 공연 등록이 생기면 등록할 때 검증한다.

1. 아래 지정 행을 넣으면 각각 어떻게 되는가?

예시 데이터에 올바른 지정 두 행이 이미 들어 있다고 본다.

show_idseat_idseat_grade_id
가150011
나250110
다150199
라250010
답 보기

가: 등급 11은 공연 1의 것이라 외래 키는 통과하지만, (1, 500) 지정이 이미 있어 기본 키에서 실패한다. 같은 공연에서 좌석 하나에 등급은 하나뿐이다.

나: 등급 10은 공연 1의 것이라 (10, 2)인 등급이 없다. 복합 외래 키에서 실패한다.

다: 등급 99가 없으므로 (99, 1)인 등급도 없다. 복합 외래 키에서 실패한다.

라: 등급 10이 공연 2의 것이 아니라서 외래 키도 어기지만, (2, 500) 지정이 이미 있어 기본 키에서 먼저 실패한다. 오류 메시지에는 기본 키 위반만 나온다.

2. 이 줄을 지우고 마이그레이션을 만들어 적용하면 어떻게 되는가?

seatGrades의 세 번째 인자를 바꾼다.

   unique().on(table.showId, table.name),
-  unique().on(table.id, table.showId),
답 보기

지정 테이블의 복합 외래 키가 가리킬 (id, show_id) 유니크 제약이 없어진다. PostgreSQL이 there is no unique constraint matching given keys for referenced table "seat_grades"로 거부하므로 마이그레이션이 실패한다. id가 기본 키라는 사실만으로는 통과하지 않는다.

3. 이 줄을 unique().on(table.showId, table.id)처럼 순서를 바꿔 써도 외래 키를 만들 수 있을까?

답 보기

만들 수 있다. PostgreSQL은 외래 키가 가리키는 컬럼들과 유니크 제약의 컬럼들이 같은 집합인지를 본다. 컬럼 순서는 인덱스 모양만 바꾼다.
