14 좌석 등급 쿼리 읽기

GET /shows/:id의 서비스 함수 findDetail()(apps/api/src/shows/shows.service.ts)에서 공연의 등급과 그 등급 좌석이 있는 구역을 읽는 쿼리를 한 줄씩 따라간다. 같은 예시 데이터로 각 단계가 표를 어떻게 바꾸는지 모든 칸을 남긴 채 본다. LEFT JOIN 개념은 db-and-drizzle 01 문서, 테이블 구조는 12 문서와 13 문서에 있다.

한눈에 보기

// 등급과 그 등급 좌석이 있는 구역을 한 행씩 읽는다. 한 구역에 등급이 섞여 있으면 그 구역이 등급마다 한 행씩 나온다.
// 좌석이 없는 등급도 빠지지 않게 LEFT JOIN으로 읽는다. 그런 등급은 구역 이름이 null인 행 하나다.
this.db
  .select({
    id: seatGrades.id,
    name: seatGrades.name,
    price: seatGrades.price,
    sectionName: sections.name,
  })
  .from(seatGrades)
  .leftJoin(
    seatGradeAssignments,
    and(
      eq(seatGradeAssignments.showId, seatGrades.showId),
      eq(seatGradeAssignments.seatGradeId, seatGrades.id),
    ),
  )
  .leftJoin(seats, eq(seats.id, seatGradeAssignments.seatId))
  .leftJoin(sections, eq(sections.id, seats.sectionId))
  .where(eq(seatGrades.showId, id))
  .groupBy(seatGrades.id, sections.id)
  // 가격이 같으면 먼저 만든 등급을 앞에 둔다. 구역은 공연장에 둔 순서(id)다.
  .orderBy(
    desc(seatGrades.price),
    asc(seatGrades.id),
    asc(sections.id),
  ),

코드에 쓴 순서는 select가 먼저지만, DB가 표를 만드는 순서는 실행 순서를 따른다. 이 문서도 그 순서로 읽는다.

  1. from 등급 테이블에서 시작한다.
  2. leftJoin × 3 등급 → 지정 → 좌석 → 구역 순서로 옆에 칸을 붙인다. 짝이 여러 개면 행이 늘고, 짝이 없으면 NULL로 채운다.
  3. where 공연 하나의 등급만 남긴다.
  4. groupBy (등급, 구역) 조합마다 한 행으로 합친다.
  5. orderBy, select 정렬하고 화면에 필요한 네 칸만 남긴다.

이 쿼리는 count 같은 집계 함수를 쓰지 않는다. 그래서 groupBy는 여기서 "(등급, 구역) 조합의 중복 제거" 역할만 한다. 등급 좌석이 구역에 몇 개 있든 구역 이름은 한 번만 나온다.

6단계: 정렬하고 칸 고르기

.orderBy(desc(seatGrades.price), asc(seatGrades.id), asc(sections.id))
  1. 가격 내림차순 비싼 등급이 먼저다. VIP석 → R석 → S석.
  2. 등급 id 오름차순 가격이 같은 등급이 있으면 먼저 만든 등급을 앞에 둔다. 이 데이터에는 없다.
  3. 구역 id 오름차순 같은 등급 안에서 공연장에 둔 구역 순서대로 둔다. R석의 A구역(1) → B구역(2).
.select({
  id: seatGrades.id,
  name: seatGrades.name,
  price: seatGrades.price,
  sectionName: sections.name,
})

왜 세 번 모두 LEFT JOIN인가

세 조인을 모두 innerJoin으로 바꾸면 1단계에서 짝이 없는 S석 행이 버려진다. 공연이 S석을 정했는데 상세 화면의 등급별 가격에서 S석이 보이지 않게 된다. 주석의 "좌석이 없는 등급도 빠지지 않게"가 이 뜻이다.

첫 조인만 LEFT로 두고 나머지를 inner로 써도 같은 일이 생긴다. 1단계에서 살린 S석 행의 seat_id가 NULL이라 2단계의 inner join에서 짝을 못 찾고 버려진다.

조인 방식최종 결과에 S석
left, left, left (지금)있다. 구역 이름 NULL
left, inner, inner없다. 2단계에서 버려짐
inner, inner, inner없다. 1단계에서 버려짐

LEFT JOIN으로 살린 행은, 그 행의 NULL 칸으로 이어지는 뒤의 조인도 LEFT로 써야 끝까지 남는다.

첫 조인 조건에 showId를 넣은 이유

and(
  eq(seatGradeAssignments.showId, seatGrades.showId),   // ① 공연이 같은가
  eq(seatGradeAssignments.seatGradeId, seatGrades.id),  // ② 등급이 같은가
)

결과는 ②만으로도 같다. 지정의 공연과 등급의 공연은 복합 외래 키가 늘 같게 지키므로, ②를 만족하는 지정 행은 ①도 저절로 만족한다. ①은 결과가 아니라 속도를 위한 조건이다.

재 보면

지정 테이블에 100만 행(공연 1,000개 × 좌석 1,000석)을 넣고 공연 하나의 등급을 읽었다. 로컬 PostgreSQL에서 EXPLAIN ANALYZE로 잰 결과다.

조인 조건지정 테이블을 읽는 방법읽은 행실행 시간
① + ② (지금 코드)기본 키 인덱스로 show_id = 500만 찾는다1,0000.4 ms
②만테이블 전체를 처음부터 끝까지 읽는다1,000,00099 ms
선택 읽기: 두 실행 계획

① + ②: 지정 테이블(sga)을 기본 키 인덱스로 읽는다.

Hash Right Join
  Hash Cond: (sga.seat_grade_id = sg.id)
  ->  Index Scan using sga_pkey on sga
        Index Cond: (show_id = 500)
  ->  Hash
        ->  Bitmap Heap Scan on sg
              Recheck Cond: (show_id = 500)

②만: 지정 테이블을 처음부터 끝까지 읽는다(Seq Scan).

Hash Right Join
  Hash Cond: (sga.seat_grade_id = sg.id)
  ->  Seq Scan on sga
  ->  Hash
        ->  Bitmap Heap Scan on sg
              Recheck Cond: (show_id = 500)

왜 차이가 나나

지정 테이블에 있는 인덱스는 기본 키 (show_id, seat_id) 하나뿐이다.

  • ②만 쓰면 seat_grade_id로 찾아야 하는데, seat_grade_id로 시작하는 인덱스가 없다. 외래 키를 걸어도 PostgreSQL은 인덱스를 만들지 않는다. 그래서 모든 행을 읽고 맞는 행을 고른다.
  • ①을 더하면 where가 seat_grades.show_id를 500으로 정했으므로, ①을 거쳐 지정 테이블도 show_id = 500으로 찾을 수 있다. 기본 키 인덱스가 show_id로 시작하므로 앞 컬럼 규칙대로 그 인덱스를 쓴다. 실행 계획의 Index Cond: (show_id = 500)이 그것이다.

①이 빠르게 만드는 이유는 "기본 키가 조합이라서"보다 "show_id로 시작하는 인덱스가 있어서"다. 지정 테이블이 id 기본 키 + UNIQUE (show_id, seat_id) 구조였어도 그 유니크 인덱스로 같은 일이 일어난다. 어느 구조든 ①을 빼면 느려진다. 그래서 shows.service.ts의 이 조건 위에 지우지 말아야 할 이유를 주석으로 적어 두었다.

3. where를 첫 조인 조건 안으로 옮기면 결과가 같을까?

 .leftJoin(
   seatGradeAssignments,

     eq(seatGradeAssignments.showId, seatGrades.showId),
     eq(seatGradeAssignments.seatGradeId, seatGrades.id),
+    eq(seatGrades.showId, id),
   ),
 )
-.where(eq(seatGrades.showId, id))

다르다. LEFT JOIN의 조건은 "짝을 찾는 조건"이라 왼쪽 행을 버리지 않는다. 스탠딩(공연 2) 행은 짝을 못 찾을 뿐 NULL 칸을 단 채 남아서, 결과에 다른 공연의 등급이 섞인다. 왼쪽 테이블을 거르는 조건은 where에 둔다(ON과 WHERE).
