03 Drizzle 쿼리 문법

서비스, 시드, 테스트에서 DB를 읽고 쓸 때 쓰는 Drizzle 쿼리 문법을 모은 참고 문서다. 문법마다 이 저장소의 코드, Drizzle이 만드는 SQL, 결과 타입을 적는다. 처음부터 읽지 않고, 다른 문서에서 링크로 넘어와 필요한 절만 읽는다. 쿼리에 쓰는 테이블 객체(shows, performances)를 정의하는 문법은 db-and-drizzle 02 문서, JOIN이나 GROUP BY 같은 SQL 개념은 db-and-drizzle 01 문서에 있다. 기준 버전은 drizzle-orm 0.45다.

쿼리는 await할 때 실행된다

const query = this.db.select().from(shows); // 아직 DB에 아무것도 보내지 않았다
const rows = await query; // 이때 SQL을 만들어 보내고 결과를 받는다

this.db.select()...는 쿼리를 바로 실행하지 않고, "어떤 SQL을 보낼지"를 담은 객체(쿼리 빌더)를 돌려준다. await하는 순간(정확히는 then이 불릴 때) SQL을 만들어 DB에 보낸다. 메서드를 이어 붙이는 동안에는 SQL 문장을 조립하기만 한다.

그래서 쿼리 일부를 변수에 담아 다른 쿼리의 재료로 쓸 수 있다. ShowsService의 period가 그 예다. period는 혼자 실행되지 않고, 바깥 쿼리의 SQL 안에 끼워 넣어진다(서브쿼리).

this.db는 DatabaseModule이 주입한 Drizzle 객체다(db-and-drizzle 00 문서).

select

await this.db
  .select({
    id: shows.id,
    title: shows.title,
    venueName: venues.name,
  })
  .from(shows)
  .innerJoin(venues, eq(venues.id, shows.venueId));
// 결과 타입: { id: number; title: string; venueName: string }[]

select에 넘기는 객체가 결과 행의 모양이다. 키는 결과에서 쓸 이름이고, 값은 가져올 컬럼이다. 키 이름은 마음대로 지을 수 있어서, venues.name을 venueName으로 받았다. SQL의 select "venues"."name"을 고르고 결과를 venueName 키에 담는 일은 Drizzle이 한다.

결과 타입은 스키마에서 자동으로 나온다. shows.title이 .notNull()이라 string이고, 수식어가 없는 컬럼이면 string | null이다(db-and-drizzle 02 문서).

쓰는 법 가져오는 것
select() 테이블의 모든 컬럼. 결과 타입은 $inferSelect와 같다
select({ id: shows.id, ... }) 고른 컬럼만, 고른 이름으로

이 저장소는 필요한 컬럼만 고르는 쪽을 쓴다. description처럼 긴 본문을 목록에서 가져오지 않고, 결과 타입이 화면에 필요한 모양과 바로 맞는다.

from

.from(shows)

어느 테이블에서 읽을지 정한다. SQL의 from "shows"다. 테이블 객체 대신 서브쿼리를 넘길 수도 있다.

innerJoin과 leftJoin

.from(shows)
.innerJoin(venues, eq(venues.id, shows.venueId))
from "shows" inner join "venues" on "venues"."id" = "shows"."venue_id"

첫 인자는 붙일 테이블(또는 서브쿼리), 둘째 인자는 짝을 찾는 조건이다. "공연의 venue_id와 같은 id를 가진 공연장을 붙인다"는 뜻이다(JOIN).

메서드 짝이 없는 행 붙인 쪽 컬럼의 결과 타입
innerJoin 결과에서 빠진다 string
leftJoin 남고, 붙인 쪽 컬럼이 NULL이다 string | null

Drizzle은 JOIN 종류에 맞춰 결과 타입도 바꾼다. leftJoin(venues, ...)이면 venueName이 string | null이 되어, 짝이 없는 경우를 코드에서 처리하라고 알려 준다.

같은 모양으로 rightJoin, fullJoin도 있고, 조건 없이 모든 조합을 만드는 crossJoin(테이블)도 있다. 각 JOIN이 짝 없는 행을 어떻게 다루는지, 일대다 관계를 JOIN하면 행이 늘어나는 이유는 db-and-drizzle 01 문서에 있다. 공연 목록이 회차를 바로 JOIN하지 않고 서브쿼리로 공연당 한 행으로 줄인 뒤 JOIN하는 것도 그 때문이다(일대다 JOIN은 행을 늘린다). 공연 목록 쿼리 전체를 예시 데이터로 따라가는 설명은 db-and-drizzle 05 문서에 있다.

eq

import { eq } from 'drizzle-orm';

eq(venues.id, shows.venueId); // "venues"."id" = "shows"."venue_id"
eq(shows.id, 3); // "shows"."id" = $1, params: [3]

"두 값이 같다"는 조건을 만든다. JOIN의 짝 조건이나 .where(...)의 조건으로 쓴다. 컬럼끼리 비교하면 SQL에 컬럼 이름이 들어가고, 값과 비교하면 값은 파라미터($1)로 따로 보낸다.

비교할 값의 타입도 검사한다. shows.id는 number이므로 eq(shows.id, '3')은 컴파일 오류다.

ne와 조건 재사용

import { ne } from 'drizzle-orm';

const isListed = ne(salesStatus.salesStatus, 'ended'); // "sales_status" <> $1, params: ['ended']

this.db.select({ ... }).from(shows).innerJoin(salesStatus, ...).where(isListed); // 목록
this.db.select({ count: count() }).from(shows).innerJoin(salesStatus, ...).where(isListed); // 개수

ne는 not equal, "두 값이 다르다"는 조건이다. SQL로는 <>다. 쓰는 법은 eq와 같다. 같은 줄의 비교 함수로 gt(>), gte(>=), lt(<), lte(<=)가 있다.

eq, ne가 돌려주는 조건도 쿼리 빌더처럼 SQL 조각을 담은 객체다. 그래서 변수에 담아 두고 여러 쿼리의 .where()에 넘길 수 있다. 목록 쿼리와 개수 쿼리가 같은 조건을 써야 할 때 이렇게 하면, 조건을 바꿀 때 한쪽만 고치는 실수를 막는다. 조건 여러 개는 and(a, b), or(a, b)로 묶는다.

비교 대상이 NULL이면 ne도 참이 되지 않는다(NULL). NULL인지 보려면 isNull(col), isNotNull(col)을 쓴다.

like, ilike

import { ilike } from 'drizzle-orm';

ilike(shows.title, '%정원%'); // "shows"."title" ilike $1, params: ['%정원%']

글자 패턴 조건을 만든다(LIKE와 ILIKE). like는 대소문자를 구분하고, ilike는 구분하지 않는다. 반대 조건은 notLike, notIlike다.

Drizzle은 패턴을 손대지 않고 파라미터로 보낸다. 앞뒤 %를 붙이는 일도, 사용자 입력 안의 %, _, \를 이스케이프하는 일도 호출하는 쪽이 한다. 이 저장소의 사례는 db-and-drizzle 09 문서에 있다.

and와 있을 수도 없을 수도 있는 조건

import { and, ilike, ne } from 'drizzle-orm';

const listCondition = and(
  ne(salesStatus.salesStatus, 'ended'),
  q ? ilike(shows.title, `%${q}%`) : undefined,
);
q만들어지는 SQL
'정원'("sales_status" <> $1 and "shows"."title" ilike $2)
null"sales_status" <> $1

and(...)와 or(...)는 인자 중 undefined를 빼고 남은 조건만 잇는다. 그래서 검색어가 있을 때만 붙는 조건을 조건 ? 식 : undefined로 바로 넘길 수 있다. 쿼리를 if로 두 벌 쓰지 않아도 된다. 남은 조건이 하나면 괄호 없이 그 조건만, 하나도 없으면 undefined를 돌려준다. .where(undefined)는 where 절을 붙이지 않는다.

자바스크립트로 치면 [a, b].filter((c) => c !== undefined).join(' and ')이다. 조건 묶음도 SQL 조각이라 ne처럼 변수에 담아 목록 쿼리와 개수 쿼리에 함께 넘긴다.

orderBy, asc, desc

import { asc } from 'drizzle-orm';

.orderBy(asc(period.start), asc(shows.id))
order by "start" asc, "shows"."id" asc

정렬 기준을 앞에서부터 차례로 적는다(ORDER BY). asc는 오름차순, desc는 내림차순이다. 서브쿼리의 별칭 컬럼(period.start)도 기준으로 쓸 수 있다.

공연 목록은 첫 회차 일시가 같은 공연끼리 순서가 흔들리지 않도록 shows.id를 마지막 기준으로 붙였다.

orderBy는 기준을 인자 여러 개로 받으므로, 조건에 따라 기준 묶음을 고를 때는 배열을 골라 펼쳐 넘긴다. 

.orderBy(
  ...(sort === 'newest'
    ? [desc(shows.createdAt), desc(shows.id)] // 최근 등록 순
    : [asc(period.start), asc(shows.id)]),    // 공연 시작일 순
)

limit, offset

.limit(PAGE_SIZE) // 20
.offset((PAGE - 1) * PAGE_SIZE) // 1페이지면 0
limit 20    -- 20은 실제로는 빈칸 $1로 따로 간다

최대 몇 개를 가져올지(limit), 앞에서 몇 개를 건너뛸지(offset) 정한다(LIMIT, OFFSET). 값은 파라미터로 보낸다.

offset(0)은 SQL에 아예 나오지 않는다. 0개를 건너뛰는 것은 건너뛰지 않는 것과 같아서 Drizzle이 뺀다. offset(20)이면 offset $2가 붙는다.

count, min, max와 groupBy

import { count, max, min } from 'drizzle-orm';

this.db
  .select({
    showId: performances.showId,
    start: min(performances.startsAt),
    end: max(performances.startsAt),
  })
  .from(performances)
  .groupBy(performances.showId);
// 결과 타입: { showId: number; start: Date | null; end: Date | null }[]
select "show_id", min("starts_at"), max("starts_at") from "performances" group by "performances"."show_id"

drizzle-orm에서 가져오는 집계 함수를 select 객체의 값으로 쓴다(집계 함수와 GROUP BY). .groupBy(...)로 묶을 기준을 정한다.

함수 결과 타입 이유
count() number 행이 없어도 0이다. DB는 큰 정수를 문자열로 주는데, Drizzle이 number로 바꿔 준다
min(col), max(col) 컬럼 타입 | null 집계할 행이 없으면 NULL이다. 컬럼이 Date면 결과도 Date로 바꿔 준다

그래서 서비스는 min, max 결과를 Date | null로 받는다. INNER JOIN으로 회차가 있는 공연만 남기므로 실제로는 null이 오지 않지만, 타입은 그것을 모른다. toIso()가 null이면 오류를 던져 타입을 Date로 좁힌다.

count()는 인자 없이 쓰면 count(*)(행 수)이고, count(col)이면 그 컬럼이 NULL이 아닌 행 수다.

헬퍼가 없는 집계는 sql로 쓴다

count() 헬퍼에는 FILTER를 붙일 방법이 없고, bool_or는 헬퍼가 아예 없다. 이럴 때는 sql 템플릿으로 직접 쓴다. 

// 예: 공연별로 묶은 회차에서 (groupBy(performances.showId))
total: count().as('total'),                // 전체 회차 수
active: sql<number>`count(*) filter (where not ${performances.isCancelled})`
  .mapWith(Number)
  .as('active'),                           // 취소되지 않은 회차 수
hasCancelled: sql<boolean>`bool_or(${performances.isCancelled})`.as('has_cancelled'), // 취소된 회차가 있는가
값쓴 방법.mapWith
total count() 헬퍼 필요 없다. 헬퍼가 안에서 숫자로 바꿔 준다
active sql로 쓴 count(*) filter (...) .mapWith(Number). count(*)는 bigint이고, 드라이버가 bigint를 문자열('3')로 준다(.mapWith)
hasCancelled sql로 쓴 bool_or(...) 필요 없다. 드라이버가 boolean은 처음부터 JS true/false로 준다

헬퍼로 만든 값이든 sql 조각이든, 서브쿼리 안에서 계산한 값이면 바깥에서 꺼내 쓸 수 있게 .as()로 이름을 붙인다(서브쿼리와 .as()).

서브쿼리와 .as()

const period = this.db
  .select({
    showId: performances.showId,
    start: min(performances.startsAt).as('start'), // ② 계산한 값에 별칭
    end: max(performances.startsAt).as('end'),
  })
  .from(performances)
  .groupBy(performances.showId)
  .as('period'); // ① 쿼리 전체에 이름

await this.db
  .select({ title: shows.title, start: period.start }) // ③ 테이블처럼 쓴다
  .from(shows)
  .innerJoin(period, eq(period.showId, shows.id));
select "shows"."title", "start" from "shows"
inner join (
  select "show_id", min("starts_at") as "start", max("starts_at") as "end"
  from "performances" group by "performances"."show_id"
) "period" on "period"."show_id" = "shows"."id"
  1. 쿼리 끝의 .as('period') 쿼리를 실행하지 않고 서브쿼리로 만든다. 괄호로 감싸 "period"라는 이름을 붙인 SQL 조각이 된다.
  2. 계산한 값의 .as('start') min(...) 같은 계산 결과에는 컬럼 이름이 없으므로 별칭을 붙인다. 붙이지 않고 바깥에서 period.start를 쓰면 Drizzle이 오류를 던진다: "You tried to reference "start" field from a subquery, which is a raw SQL field, but it doesn't have an alias declared."
  3. 테이블처럼 쓰기 period.showId, period.start처럼 select 객체의 키로 컬럼을 꺼내 from, innerJoin, orderBy, select에 쓴다. 타입도 그대로 따라온다.

showId: performances.showId처럼 테이블 컬럼을 그대로 고른 값은 이미 컬럼 이름(show_id)이 있어서 별칭이 필요 없다.

서브쿼리를 돌려주는 함수

// apps/api/src/shows/show-sales-status.ts
export function showSalesStatusSubquery(db: Database, { now }: { now: Date }) {
  return db
    .select({ showId: performances.showId, salesStatus: /* ... */, salesOpenAt: /* ... */ })
    .from(performances)
    .groupBy(performances.showId)
    .as('show_sales_status');
}

// 쓰는 곳
const salesStatus = showSalesStatusSubquery(this.db, { now: this.clock.now() });
this.db.select({ status: salesStatus.salesStatus }).from(shows).innerJoin(salesStatus, eq(salesStatus.showId, shows.id));

서브쿼리도 실행 전의 객체라서 함수가 만들어 돌려줄 수 있다. 여러 쿼리가 같은 계산을 JOIN해야 할 때(예: 공연 목록과 공연 상세가 같은 공연 판매 상태를 써야 할 때) 계산을 한 곳에 둘 수 있다. 계산에 필요한 값(now)은 인자로 받는다. 함수를 부를 때마다 새 서브쿼리 객체가 생기므로, 한 쿼리 안에서는 한 번 만든 객체를 같이 쓴다.

쿼리 두 개를 함께 보내기

const [rows, [total]] = await Promise.all([
  this.db.select({ ... }).from(shows) /* ... */.limit(20),
  this.db.select({ count: count() }).from(shows).innerJoin(salesStatus, eq(salesStatus.showId, shows.id)).where(isListed),
]);

쿼리 빌더는 await할 수 있는 객체라 Promise.all에 그대로 넣을 수 있다. 두 쿼리가 서로를 기다리지 않고 함께 DB로 간다. Drizzle 객체 안의 pg 연결 풀이 연결 두 개로 나눠 보낸다(db-and-drizzle 00 문서).

select의 결과는 항상 배열이다. 개수 쿼리는 행이 하나뿐이어도 [{ count: 21 }]로 오므로 [total]로 꺼낸다. API의 tsconfig에는 noUncheckedIndexedAccess가 없어서 TypeScript는 total을 항상 있는 값({ count: number })으로 본다. count(*)는 행이 없어도 결과 행 하나를 돌려주므로 실제로도 비지 않지만, 서비스는 total?.count ?? 0으로 한 번 더 막아 둔다.

두 쿼리는 서로 다른 연결에서 따로 실행되므로, 그 사이에 공연이 추가되면 목록과 전체 개수가 어긋날 수 있다. 공연 목록에서는 다음 요청에서 맞춰지므로 감수한다. 반드시 같은 시점의 값이어야 하면 트랜잭션과 격리 수준을 함께 정해야 한다.

insert, values, returning

시드는 구역 하나의 좌석을 문장 하나로 한꺼번에 넣는다(실제 코드에서 줄였다).

const sectionSeats = await tx
  .insert(seats)
  .values([
    { sectionId: section.id, row: 'A', number: 1 },
    { sectionId: section.id, row: 'A', number: 2 },
    // ... 열 수 × 열당 좌석 수만큼
  ])
  .returning({ id: seats.id });
// 결과 타입: { id: number }[]
insert into "seats" ("id", "section_id", "row", "number")
values (default, $1, $2, $3), (default, $4, $5, $6)  -- 값 1, 'A', 1, 1, 'A', 2는 따로 간다
returning "id"
  • .insert(테이블): 어느 테이블에 넣을지 정한다.
  • .values(객체 또는 배열): 넣을 행이다. 배열을 넘기면 문장 하나로 여러 행을 넣는다. 값의 타입은 $inferInsert라서, 필수 컬럼을 빠뜨리거나 id를 넣으면 컴파일 오류다(db-and-drizzle 02 문서). 빈 배열을 넘기면 실행할 때 오류가 나므로, 넣을 행이 없으면 부르지 않는다.
  • .returning({...}): 넣은 행에서 돌려받을 컬럼을 고른다. DB가 매긴 id처럼 넣은 뒤에야 알 수 있는 값을 받을 때 쓴다. 시드는 좌석을 넣고 받은 id로 회차 좌석을 만든다. 공연장, 구역, 공연, 회차는 하나씩 넣고 받은 id로 그 아래 행을 넣는다. returning이 없으면 결과에 행이 없다.

(default, $1, $2, $3)의 default는 id를 DB가 정하게 하는 SQL 표기다. 행을 여러 개 넣을 때 각 행의 값이 $1, $2… 빈칸으로 따로 간다.

execute와 sql 템플릿

import { sql } from 'drizzle-orm';

await tx.execute(
  sql`TRUNCATE ${performanceSeats}, ${performances}, ${shows}, ${seats}, ${sections}, ${venues} RESTART IDENTITY`,
);
// → TRUNCATE "performance_seats", "performances", "shows", "seats", "sections", "venues" RESTART IDENTITY

쿼리 빌더에 없는 SQL은 sql 태그드 템플릿으로 직접 쓰고 execute로 보낸다. TRUNCATE는 빌더 메서드가 없어서 이렇게 썼다.

${...}에 넣은 것 SQL에 들어가는 모양
테이블 객체(${shows}) 테이블 이름 "shows"
컬럼 객체(${shows.title}) 컬럼 이름 "shows"."title"
값(${keyword}) 파라미터 $1. 값은 따로 보낸다

값이 자동으로 파라미터가 되므로, 템플릿 리터럴처럼 보여도 문자열을 이어 붙이는 것과 달리 SQL 인젝션에 안전하다. 테이블 이름을 문자열로 적지 않고 객체로 넣으면, 스키마에서 이름을 바꿨을 때 이 SQL도 함께 바뀐다.

통합 테스트는 db.execute('TRUNCATE performance_seats, performances, shows, seats, sections, venues RESTART IDENTITY CASCADE')처럼 문자열을 그대로 넘긴다. 값이 섞이지 않는 고정 문장이라 문제는 없지만, 테이블 이름이 바뀌어도 타입 검사가 잡아 주지 않는다.

sql은 select 객체의 값으로도 쓸 수 있다. 예: sql<number>`count(*)`. 제네릭으로 결과 타입을 알려 주지만, Drizzle은 그 타입이 맞는지 검사하지 않는다.

sql 조각으로 식 조립하기

Drizzle에 함수가 없는 SQL(예: CASE, FILTER)은 sql 템플릿으로 식을 직접 만든다. sql`...`이 돌려주는 값을 SQL 조각(타입 이름 SQL)이라고 부른다. 조각은 실행되지 않는 SQL 텍스트와 파라미터의 묶음이다. 

import { type SQL, sql } from 'drizzle-orm';

// 조각을 돌려주는 함수 (실제 코드에서 when 갈래를 줄였다)
function performancePriority({ now }: { now: Date }): SQL<number> {
  return sql<number>`case
    when ${performances.isCancelled} or ${performances.startsAt} <= ${now} then 2
    else 0
  end`;
}

const priority = performancePriority({ now });
const showPriority = sql`min(${priority})`; // 조각 안에 조각을 넣는다
min(case
    when "performances"."is_cancelled" or "performances"."starts_at" <= '2026-11-10 12:00+09' then 2
    -- '2026-11-10 12:00+09'은 now(한국 시각). 실제로는 빈칸 $1로 따로 간다
    else 0
  end)

${...}에 넣을 수 있는 것

execute 절의 표에 하나가 더 있다. 다른 SQL 조각을 넣으면 그 조각의 SQL이 그 자리에 그대로 끼워지고, 조각의 파라미터도 함께 따라온다. 그래서 작은 조각을 함수로 만들어 두고 레고처럼 쌓아 큰 식을 만들 수 있다.

Date 같은 값을 넣으면 다른 값처럼 파라미터가 된다. pg 드라이버가 보낼 때 시간대가 붙은 시각 문자열로 바꾸고, PostgreSQL은 starts_at(timestamptz)과 비교하는 것을 보고 그 파라미터를 timestamptz로 읽는다.

sql<T>는 타입 약속이다

sql<number>의 <number>는 TypeScript에게 "이 식의 결과는 number다"라고 알려 주기만 한다. 실행할 때 값을 바꾸거나 검사하지 않는다. as number처럼 틀리게 적어도 컴파일러가 모른다. 값을 실제로 바꾸려면 .mapWith()를 붙인다.

select에 넣을 때는 .as()

.select({
  salesStatus: sql<ShowSalesStatus>`case ${showPriority} ${toStatus} end`.as('sales_status'),
})

조각을 서브쿼리의 결과로 내보낼 때는 컬럼 이름이 없으므로 .as('이름')으로 별칭을 붙인다. min(...).as('start')와 같은 이유다.

조각은 넣는 곳마다 펼쳐진다. 자바스크립트 변수 priority는 하나지만, SQL에는 넣은 횟수만큼 같은 식이 복사되고 파라미터도 그만큼 늘어난다. JS 변수가 SQL 변수가 되지는 않는다. 아래 코드는 같은 CASE를 SQL에 세 번 쓰고 now를 파라미터 세 개($1~$3)로 보낸다. 

sql`min(${priority})`;
sql`min(${priority}) = 1`;
sql`filter (where ${priority} = 1)`;

결과는 맞지만 SQL이 길어지고 DB가 같은 계산을 여러 번 한다. 한 번만 계산하려면 그 식을 안쪽 서브쿼리의 컬럼으로 먼저 만들고 바깥 쿼리에서 이름으로 부른다.

sql.raw: 문자열을 SQL에 그대로 넣기

sql`then ${2}`; // then $1, params: [2]
sql`then ${sql.raw('2')}`; // then 2
sql`then ${sql.raw(`'on_sale'`)}`; // then 'on_sale'

sql.raw(문자열)은 문자열을 파라미터로 보내지 않고 SQL 문장에 글자 그대로 박아 넣는다. ${...}에 그냥 값을 넣는 것과 정반대다.

sql.raw에 사용자 입력을 넣으면 그대로 SQL 인젝션이다. 코드에 고정된 상수에만 쓴다. React의 dangerouslySetInnerHTML과 같은 무게로 다룬다.

상수인데 왜 파라미터로 보내지 않았나

파라미터에는 타입이 붙어 있지 않다. DB는 파라미터 주변을 보고 타입을 짐작하는데, CASE의 결과 자리가 모두 파라미터면 짐작할 단서가 없어 text로 정한다. 그러면 숫자로 쓰려던 값이 문자로 비교된다. 이 저장소의 PostgreSQL 18에서 확인한 결과다. 

-- 결과 자리가 파라미터: 타입이 text가 된다
PREPARE p AS SELECT pg_typeof(CASE WHEN true THEN $1 ELSE $2 END);
EXECUTE p(2, 10);                                  -- text

-- text끼리 min을 구하면 글자 순서로 비교한다
min('10', '9') → '10'                              -- '1'이 '9'보다 앞이라서

-- 결과 자리가 숫자 리터럴: integer가 된다
SELECT pg_typeof(CASE WHEN true THEN 2 ELSE 0 END); -- integer

그래서 판매 상태 순번(0~2)과 상태 이름('on_sale')처럼 코드에 고정된 상수는 sql.raw로 리터럴로 넣었다. SQL을 읽을 때도 then $3보다 then 2가 뜻이 바로 보인다. 반대로 now처럼 실행할 때마다 달라지는 값은 파라미터로 보낸다. 

// apps/api/src/shows/show-sales-status.ts
function priorityOf(status: ShowSalesStatus): SQL {
  return sql.raw(String(SHOW_SALES_STATUSES.indexOf(status))); // 'ended' → 2
}
function literalOf(status: ShowSalesStatus): SQL {
  return sql.raw(`'${status}'`); // 'on_sale' → 'on_sale'(작은따옴표 포함)
}

인자 타입이 ShowSalesStatus라서 정해진 세 값 말고는 들어올 수 없다. 이렇게 타입으로 입력을 막아 두면 sql.raw를 써도 안전하다는 것을 코드만 보고 알 수 있다.

sql.join: 조각 배열을 하나로 잇기

const toStatus = sql.join(
  SHOW_SALES_STATUSES.map((status) => sql`when ${priorityOf(status)} then ${literalOf(status)}`),
  sql` `, // 조각 사이에 넣을 구분자
);
when 0 then 'on_sale' when 1 then 'upcoming' when 2 then 'ended'

sql.join(조각 배열, 구분자)는 Array.prototype.join의 SQL 조각 버전이다. 문자열이 아니라 조각을 잇기 때문에, 각 조각의 파라미터도 순서대로 함께 이어진다. 구분자도 조각으로 넘긴다. 쉼표로 이으려면 sql`, `를 넘긴다.

배열에서 SQL을 만들면 배열이 바뀔 때 SQL도 따라 바뀐다. 판매 상태를 하나 더하면 배열에 한 줄만 넣으면 되고, 순번과 위 매핑은 다시 손으로 고치지 않는다.

.mapWith: DB 값을 JS 값으로 바꾸기

salesOpenAt: sql<Date | null>`case when ... then min(${performances.salesOpenAt}) end`
  .mapWith(performances.salesOpenAt) // timestamptz 컬럼과 같은 방법으로 바꾼다 → Date
  .as('sales_open_at'),

DB가 돌려준 값은 드라이버를 거쳐 문자열 같은 원시 값으로 올 수 있다. 테이블 컬럼을 고르면 Drizzle이 컬럼 정의를 보고 알맞은 JS 값(예: timestamptz → Date)으로 바꿔 준다. 그런데 직접 쓴 sql 조각은 Drizzle이 무슨 값인지 모르므로 바꾸지 않고 그대로 넘긴다.

.mapWith(...)는 이 조각의 결과를 어떻게 바꿀지 알려 준다.

  • 컬럼을 넘기면 그 컬럼과 같은 방법으로 바꾼다. .mapWith(performances.salesOpenAt)이면 Date가 된다. NULL은 바꾸지 않고 null로 둔다.
  • 함수를 넘기면 그 함수로 바꾼다. 예: sql`count(*)`.mapWith(Number). PostgreSQL은 큰 정수를 문자열로 주므로 숫자로 바꿀 때 쓴다.

sql<Date | null>(타입 약속)과 .mapWith(실제 변환)는 짝이다. 타입만 적고 .mapWith를 빼면, TypeScript는 Date라고 믿는데 실제로는 문자열이 와서 .toISOString()이 실행 중에 실패할 수 있다. min(col)이 따로 말하지 않아도 Date를 돌려주는 것은, Drizzle의 min 헬퍼가 안에서 mapWith(col)을 해 주기 때문이다.

이 저장소가 쓰는 node-postgres 드라이버에서 Drizzle은 timestamptz를 Date로 바꾸지 않고 문자열 그대로 받도록 설정해 두고, 컬럼 정의를 보고 직접 바꾼다. 그래서 조각에 .mapWith를 빼면 정말로 문자열이 온다. min() 헬퍼도 컬럼이 아닌 조각을 넘기면(min(sql`...`)) 결과를 String으로 바꾼다. 판매 오픈 일시는 min을 CASE와 FILTER로 감싸야 해서 헬퍼를 쓸 수 없었고, 직접 쓴 조각이라 .mapWith(performances.salesOpenAt)을 붙였다.

transaction

await db.transaction(async (tx) => {
  await tx.execute(sql`TRUNCATE ${performanceSeats}, ${performances}, ${shows}, ${seats}, ${sections}, ${venues} RESTART IDENTITY`);
  const [venue] = await tx.insert(venues).values({ name: layout.name }).returning({ id: venues.id });
  // ... 구역, 좌석, 공연, 회차, 회차 좌석을 넣는다
});

콜백 안의 쿼리를 트랜잭션 하나로 묶는다.

  • 콜백이 끝까지 실행되면 커밋한다. 이때 모든 변경이 한꺼번에 반영된다.
  • 콜백 안에서 오류가 던져지면 롤백하고, 그 오류를 다시 던진다. 앞에서 실행한 TRUNCATE도 되돌아간다.
  • 콜백 안에서는 반드시 db가 아니라 인자로 받은 tx로 쿼리한다. db로 보낸 쿼리는 다른 연결에서 실행되어 트랜잭션에 묶이지 않는다.

tx는 db와 같은 메서드(select, insert, execute)를 갖는다. 안에서 tx.rollback()을 부르면 오류를 던져 직접 롤백할 수도 있다.

toSQL로 SQL 확인하기

console.log(this.db.select({ id: shows.id }).from(shows).limit(20).toSQL());
// { sql: 'select "id" from "shows" limit $1', params: [20] }

쿼리 빌더 끝에 .toSQL()을 붙이면 DB에 보내지 않고 만들어질 SQL과 파라미터를 돌려준다. 이 문서의 SQL 예시도 이 방법으로 확인했다. DB 연결이 필요 없으므로, 쿼리가 예상한 SQL을 만드는지 빠르게 볼 때 쓴다.
