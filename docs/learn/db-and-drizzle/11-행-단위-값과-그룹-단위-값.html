11 행 단위 값과 그룹 단위 값, 함수 종속성

GROUP BY 쿼리에서 어떤 값을 SELECT에 그대로 쓸 수 있고 어떤 값은 집계로 감싸야 하는지를, 값을 행 단위와 그룹 단위로 나누는 방법으로 설명한다. 기본 키로 묶으면 다른 컬럼을 집계 없이 쓸 수 있는 이유(함수 종속성)도 함께 다룬다.

한 칸에는 값 하나

집계 함수와 GROUP BY의 기본은 db-and-drizzle 01 문서의 집계 함수와 GROUP BY에 있다. 이 문서는 그 위에서 "왜 이 값은 되고 저 값은 안 되나"를 판단하는 방법 하나를 익힌다.

행 단위 값은 행마다 하나씩 있는 값이다. 그룹 단위 값은 묶음마다 하나씩 있는 값이다. GROUP BY가 있으면 결과는 묶음당 한 줄이므로, SELECT에는 그룹 단위 값만 올 수 있다.

결과 표의 한 칸에는 값이 하나만 들어간다. 묶음 하나에 행이 여러 개 들어 있는데, 행마다 다른 값을 그 칸에 넣으려 하면 "여러 개 중 무엇을 넣지?"라는 질문에 답할 수 없다. PostgreSQL의 다음 에러가 바로 이 질문이다. 

ERROR: column "performances.starts_at" must appear in the GROUP BY clause
       or be used in an aggregate function

자바스크립트로 비유하면 행 단위 값은 rows.map((row) => ...)의 콜백 안에서만 쓸 수 있는 값이고, 그룹 단위 값은 rows.length나 rows.reduce(...)처럼 배열 전체에서 하나로 나오는 값이다.

행 단위 값

GROUP BY도 집계 함수도 없는 쿼리에서는 입력 한 행이 결과 한 행이 된다. 이때 SELECT의 값은 모두 행마다 계산되는 행 단위 값이다. 

SELECT id,
       starts_at,
       case when is_cancelled then '취소' else '정상' end AS state
FROM performances;
id starts_at state
11 3월 1일 19:30 정상
12 3월 2일 14:00 취소
21 3월 5일 20:00 정상

컬럼(id, starts_at)과 컬럼으로 만든 식(case)은 모두 행 단위다. case는 행 하나의 값을 받아 값 하나를 돌려주는 계산기라서, 행을 합치지 않는다. 자바스크립트의 performances.map((row) => ...)과 같다.

그룹 단위 값

GROUP BY show_id를 붙이면 회차 행이 공연별 묶음으로 모이고, 결과는 묶음마다 한 줄이 된다.

묶음 (show_id) 묶음에 들어간 행
1 회차 11 (3월 1일 19:30, false), 회차 12 (3월 2일 14:00, true)
2 회차 21 (3월 5일 20:00, false)

결과 표의 공연 1 줄에 각 값을 넣어 보면 무엇이 되고 무엇이 안 되는지 보인다.

SELECT에 쓴 값 공연 1 줄에 들어갈 값 종류 가능?
show_id 1 그룹 된다. 묶은 기준이라 묶음 안에서 모두 같다
count(*) 2 그룹 된다. 두 행을 개수 하나로 줄였다
min(starts_at) 3월 1일 19:30 그룹 된다. 두 값을 최솟값 하나로 줄였다
starts_at 3월 1일 19:30? 3월 2일 14:00? 행 안 된다. 후보가 둘이다
is_cancelled false? true? 행 안 된다. 후보가 둘이다

공연 2 묶음에는 회차가 하나뿐이라 starts_at도 값이 하나다. 그래도 PostgreSQL은 거절한다. 데이터를 보고 판단하지 않고, 값이 하나라는 것이 쿼리 모양만으로 보장되는지로 판단하기 때문이다. 내일 회차가 하나 더 생겨도 쿼리가 깨지지 않아야 하니까.

그룹 단위로 인정받는 값

  1. GROUP BY에 적은 컬럼이나 식 위 예의 show_id. 묶은 기준이므로 묶음 안에서 모두 같다.
  2. 집계 함수의 결과 count, min, max, sum, bool_or 등. 여러 행을 값 하나로 줄인다.
  3. GROUP BY에 기본 키를 적은 테이블의 다른 컬럼 GROUP BY performances.id면 performances.starts_at도 그룹 단위다. 이것이 함수 종속성이다.
  4. 상수와 파라미터 'on_sale', now처럼 쿼리 전체에서 하나인 값.
  5. 위 값들로만 만든 식 count(*) >= 2, case when min(starts_at) < now then ... end 등.

식을 조합할 때의 규칙

식이 복잡해도 아래 네 규칙으로 종류를 정할 수 있다.

규칙 1: 연산자, case, 일반 함수는 종류를 그대로 물려받는다

식 입력의 종류 결과의 종류
starts_at < '2026-03-02' 행 행
case when is_cancelled then 0 else 1 end 행 행
count(*) + 1 그룹 그룹
case when count(*) >= 2 then '여러 회차' end 그룹 그룹

case는 행을 합치지 못한다. 입력이 행 단위면 결과도 행 단위, 입력이 그룹 단위면 결과도 그룹 단위다.

규칙 2: 집계 함수만 행 단위를 그룹 단위로 바꾼다

min(starts_at)                                   -- 행 단위 starts_at들 → 그룹 단위 하나
sum(case when is_cancelled then 0 else 1 end)    -- 행 단위 0/1들 → 그룹 단위 합 하나
count(*) filter (where is_cancelled)             -- FILTER 조건도 행 단위로 평가된다

집계 함수 괄호 안과 FILTER 조건 안은 행 단위 세상이다. 그 행의 어떤 컬럼이든 쓸 수 있다. 괄호를 빠져나오는 순간 그룹 단위가 된다.

규칙 3: 행 단위와 그룹 단위를 섞으면 행 단위가 된다

SELECT show_id, starts_at - min(starts_at) FROM performances GROUP BY show_id;
-- ERROR: column "performances.starts_at" must appear in the GROUP BY clause ...

min(starts_at)은 그룹 단위지만 앞의 starts_at이 행 단위라서, 식 전체가 "어느 회차의 starts_at에서 빼지?"가 된다. 하나라도 행 단위가 섞이면 결과는 행 단위다.

규칙 4: 집계 안에 집계를 넣을 수 없다

SELECT max(count(*)) FROM performances GROUP BY show_id;
-- ERROR: aggregate function calls cannot be nested

count(*)는 이미 그룹 단위라 묶음 안에 값이 하나뿐이다. 다시 줄일 여러 행이 없다. "공연별 회차 수 중 최댓값"이 필요하면 공연별로 센 결과를 서브쿼리로 감싸고 바깥에서 다시 max를 구한다.

절마다 쓸 수 있는 값

실행 순서로 보면, GROUP BY를 기준으로 앞은 행 단위 세상이고 뒤는 그룹 단위 세상이다.

행 단위 세상
  1. FROM / JOIN
  2. WHERE
그룹 단위 세상 (GROUP BY가 있을 때)
  1. GROUP BY: 묶고 집계
  2. HAVING
  3. SELECT
  4. ORDER BY
절 쓸 수 있는 값 예
WHERE 행 단위만 where is_cancelled = false는 된다. where count(*) >= 2는 아직 묶음이 없어서 aggregate functions are not allowed in WHERE 에러다
HAVING 그룹 단위만 having count(*) >= 2는 된다. having is_cancelled는 행 단위라 에러다
SELECT 그룹 단위만 이 문서 전체의 주제
ORDER BY 그룹 단위만 group by show_id order by starts_at은 "묶음을 어느 회차의 시각으로 정렬하지?"라서 에러다. order by min(starts_at)은 된다

GROUP BY가 없는 쿼리는 SELECT와 ORDER BY도 행 단위 세상이다. 단, 집계 함수가 하나라도 있으면 아래 케이스 1처럼 전체가 한 묶음이 된다.

케이스 모음

케이스마다 쿼리, 묶음, 결과(또는 에러)를 함께 적는다. 결과 표의 칸이 그룹 단위 값으로만 채워지는지 확인하며 읽는다.

케이스 1: GROUP BY 없이 집계하면 전체가 한 묶음이다

SELECT count(*) FROM performances;
count
3

집계 함수가 있으면 GROUP BY가 없어도 테이블 전체가 묶음 하나가 된다. 그래서 행 단위 컬럼을 함께 쓰면 같은 에러가 난다. 

SELECT starts_at, count(*) FROM performances;
-- ERROR: column "performances.starts_at" must appear in the GROUP BY clause ...

행이 하나도 없어도 결과는 한 줄이다. count(*)는 0, max(...)는 NULL이 나온다. 반면 GROUP BY가 있으면 묶음이 하나도 없으니 결과도 0줄이다.

케이스 2: 공연별로 묶어 세고 최솟값, 최댓값 구하기

SELECT show_id,
       count(*)                              AS performance_count,
       min(starts_at)                        AS first_at,
       max(starts_at)                        AS last_at,
       count(*) filter (where is_cancelled)  AS cancelled_count
FROM performances
GROUP BY show_id;
show_id performance_count first_at last_at cancelled_count
1 2 3월 1일 19:30 3월 2일 14:00 1
2 1 3월 5일 20:00 3월 5일 20:00 0

show_id는 묶은 기준, 나머지는 모두 집계라서 전부 그룹 단위다. filter 안의 is_cancelled는 행 단위지만 집계 안이라 괜찮다(규칙 2). 이 저장소의 공연 기간 서브쿼리 (apps/api/src/shows/shows.service.ts의 buildShowPeriodSubquery)가 이 모양이다.

케이스 3: case가 집계 밖에 있을 때와 안에 있을 때

SELECT show_id,
       case when count(*) >= 2 then '여러 회차' else '한 회차' end AS label,   -- 집계 밖
       sum(case when is_cancelled then 0 else 1 end)              AS active      -- 집계 안
FROM performances
GROUP BY show_id;
show_id label active
1 여러 회차 1
2 한 회차 1
  • label의 case는 입력이 count(*)(그룹 단위)라서 결과도 그룹 단위다. 묶음마다 한 번 평가된다.
  • active의 case는 입력이 is_cancelled(행 단위)라서 결과도 행 단위다. 공연 1이면 회차 11에서 1, 회차 12에서 0이 나온다. 그 값들을 sum이 묶음마다 1로 줄인다.

같은 case라도 무엇을 입력으로 받느냐에 따라 종류가 갈린다. 집계 괄호 안에 있으면 행 단위, 밖에 있으면 그룹 단위 입력만 받을 수 있다.

케이스 4: 집계 밖의 case에 행 단위 값을 넣으면 에러

SELECT show_id,
       case when is_cancelled then '취소 있음' else '없음' end
FROM performances
GROUP BY show_id;
-- ERROR: column "performances.is_cancelled" must appear in the GROUP BY clause ...

공연 1 묶음에는 is_cancelled가 false와 true 둘이다. 어느 값으로 case를 평가할지 정할 수 없다. "회차 중 하나라도 취소면"이라는 뜻이었다면 집계로 바꾼다. 

case when bool_or(is_cancelled) then '취소 있음' else '없음' end
-- 또는
case when count(*) filter (where is_cancelled) > 0 then '취소 있음' else '없음' end

집계로 바꿀 때는 "여러 값을 어떻게 하나로 볼지"를 정해야 한다. 하나라도 참인지(bool_or), 모두 참인지(bool_and), 가장 이른 값(min)인지. 이 결정이 곧 도메인 규칙이다.

케이스 5: 묶음을 거를 때는 WHERE가 아니라 HAVING

-- 회차가 두 개 이상인 공연만
SELECT show_id, count(*) FROM performances GROUP BY show_id HAVING count(*) >= 2;
show_id count
1 2

"취소되지 않은 회차만 세기"처럼 행을 거르는 조건은 WHERE(행 단위), "회차가 두 개 이상인 공연"처럼 묶음을 거르는 조건은 HAVING(그룹 단위)에 쓴다.

케이스 6: GROUP BY에 식을 쓰면 그 식이 그룹 단위다

SELECT starts_at < '2026-03-02' AS before_mar_2, count(*)
FROM performances
GROUP BY starts_at < '2026-03-02';
before_mar_2 count
false 2
true 1

묶은 기준은 starts_at이 아니라 starts_at < '2026-03-02'라는 식이다. 그래서 이 식 자체는 그룹 단위지만, starts_at은 여전히 행 단위다(false 묶음에 3월 2일, 3월 5일이 섞여 있다). PostgreSQL은 GROUP BY before_mar_2처럼 SELECT의 별칭으로 묶는 것도 허용한다. 표준 SQL에는 없는 확장이다.

JOIN이 행을 불린다

GROUP BY는 원래 테이블이 아니라 FROM과 JOIN을 마친 결과에 적용된다. 일대다 관계를 JOIN하면 부모 행이 자식 수만큼 복사되어 늘어난다. 

SELECT * FROM performances p
JOIN performance_seats ps ON ps.performance_id = p.id;
p.id p.show_id p.starts_at ps.id ps.is_sold
11 1 3월 1일 19:30 101 true
11 1 3월 1일 19:30 102 false
11 1 3월 1일 19:30 103 false
12 1 3월 2일 14:00 201 false
12 1 3월 2일 14:00 202 false
21 2 3월 5일 20:00 301 true
21 2 3월 5일 20:00 302 true

회차 3행이 7행이 됐다. performances에서 id가 기본 키라 행마다 하나였어도, JOIN 결과에서는 같은 p.id가 여러 번 나온다. 그래서 회차별로 좌석을 세려면 p.id로 다시 묶어야 한다.

케이스 7: 회차별 좌석 수 세기

SELECT p.id,
       p.starts_at,
       count(ps.id)                              AS total_seats,
       count(ps.id) filter (where not ps.is_sold) AS remaining_seats
FROM performances p
JOIN performance_seats ps ON ps.performance_id = p.id
GROUP BY p.id;
id starts_at total_seats remaining_seats
11 3월 1일 19:30 3 2
12 3월 2일 14:00 2 2
21 3월 5일 20:00 2 0
값 종류 이유
p.id 그룹 GROUP BY에 적은 컬럼
p.starts_at 그룹 p.id가 performances의 기본 키라서. 집계 함수가 아닌데도 된다. 함수 종속성
count(ps.id) 그룹 집계
ps.is_sold 행 회차 11 묶음 안에서 true, false, false로 다르다. 그대로 쓰면 에러

케이스 8: 불어난 행을 모르고 세면 숫자가 틀린다

같은 JOIN에서 공연별로 묶고 회차 수를 세려 하면 이렇게 된다.

SELECT p.show_id, count(*), count(distinct p.id)
FROM performances p
JOIN performance_seats ps ON ps.performance_id = p.id
GROUP BY p.show_id;
show_id count(*) count(distinct p.id)
1 5 2
2 2 1

count(*)는 회차 수가 아니라 JOIN으로 불어난 행 수(좌석 수)를 센다. 에러가 나지 않아서 알아채기 어렵다. 집계 전에 "지금 한 묶음에 무엇이 몇 줄 들어 있나"를 그려 보면 피할 수 있다. 회차 수가 필요하면 count(distinct p.id)를 쓰거나, 좌석 JOIN 없이 따로 센다.

LEFT JOIN과 count(*)

이 저장소의 회차 쿼리는 LEFT JOIN을 쓴다. LEFT JOIN에서 짝이 없는 부모 행은 자식 컬럼이 모두 NULL인 행 하나로 남는다. count(*)는 이 행도 세서 1이 되고, count(ps.id)는 NULL을 세지 않아 0이 된다. 그래서 자식 수를 셀 때는 count(자식.id)를 쓴다.

함수 종속성

케이스 7에서 p.starts_at은 집계 함수도 아니고 GROUP BY에도 없는데 쓸 수 있었다. 이 절은 그 이유를 다룬다.

뜻: A가 정해지면 B가 하나로 정해진다

함수 종속성: 컬럼 A의 값을 알면 컬럼 B의 값이 하나로 정해질 때, "B는 A에 함수 종속이다"라고 한다. 수학의 함수처럼 입력(A) 하나에 출력(B)이 하나라서 붙은 이름이다.

performances에서 id는 기본 키라 같은 id를 가진 행이 하나뿐이다. 그러니 id를 알면 그 행이 정해지고, 그 행의 starts_at, show_id, is_cancelled도 하나로 정해진다. 기본 키가 정해지면 그 테이블의 모든 컬럼이 정해진다.

자바스크립트로는 id를 키로 둔 Map과 같다.

const performanceById = new Map([
  [11, { showId: 1, startsAt: '3월 1일 19:30', isCancelled: false }],
  [12, { showId: 1, startsAt: '3월 2일 14:00', isCancelled: true }],
]);

performanceById.get(11)!.startsAt; // id 하나 → startsAt 하나. Map은 키가 겹칠 수 없으니까

반대 방향은 성립하지 않는다. show_id = 1을 알아도 starts_at은 3월 1일일 수도, 3월 2일일 수도 있다. starts_at은 show_id에 함수 종속이 아니다.

GROUP BY와의 관계

GROUP BY p.id로 묶으면 한 묶음 안의 행은 모두 p.id가 같다. p.starts_at이 p.id에 함수 종속이므로, 한 묶음 안의 p.starts_at도 모두 같다. 값이 하나로 정해지니 그룹 단위로 인정된다.

묶음 (p.id) 묶음 안의 p.starts_at 묶음 안의 ps.is_sold
11 19:30, 19:30, 19:30 → 하나 true, false, false → 여럿
12 14:00, 14:00 → 하나 false, false → 지금은 같지만 보장 없음

JOIN으로 행이 불어나도 performances 쪽 컬럼은 회차 11의 한 행을 세 번 복사한 것뿐이다. 그래서 같은 값이라는 게 보장된다. 회차 12의 ps.is_sold가 우연히 둘 다 false인 것과는 다르다.

함수 종속성이 없다면 GROUP BY p.id, p.starts_at, p.show_id, p.is_cancelled처럼 쓰려는 컬럼을 모두 GROUP BY에 나열해야 한다. 결과는 같다. 이미 p.id로 나뉜 묶음이 더 쪼개지지 않으니까.

PostgreSQL이 인정하는 조건

GROUP BY에 어떤 테이블의 기본 키 컬럼이 모두 들어 있으면, 그 테이블의 다른 컬럼은 집계 없이 쓸 수 있다.

PostgreSQL은 데이터를 보지 않고 쿼리를 분석할 때 스키마의 기본 키 제약만 보고 판단한다. 데이터가 몇 행이든 결과가 같다. 이 규칙은 SQL 표준에 있고 PostgreSQL은 9.1부터 지원한다. MySQL도 ONLY_FULL_GROUP_BY 모드(5.7부터 기본)에서 비슷하게 동작한다.

함수 종속성으로 인정하지 않는 경우

논리적으로는 값이 하나로 정해지는데도 PostgreSQL이 인정하지 않는 경우가 있다. PostgreSQL은 "같은 테이블의 기본 키" 하나만 근거로 쓰기 때문이다. 아래는 모두 PostgreSQL 18에서 에러를 확인한 경우다.

경우 쿼리 논리적으로는 PostgreSQL
UNIQUE NOT NULL 컬럼으로 묶음 GROUP BY s.title 후 s.id title이 유일하면 행이 하나 에러. 기본 키만 인정한다
외래 키를 따라간 부모 컬럼 GROUP BY p.id 후 s.title 회차 하나에 공연은 하나 에러. shows의 기본 키가 GROUP BY에 없다
JOIN 조건으로 같은 값인 컬럼 GROUP BY ps.performance_id 후 p.starts_at JOIN 조건상 p.id와 같은 값 에러. p.id로 묶은 게 아니다
복합 기본 키의 일부 기본 키 (a, b)인데 GROUP BY a a만으로는 행이 여럿 에러. 기본 키 컬럼이 모두 있어야 한다
서브쿼리 결과의 컬럼 FROM (SELECT * FROM shows) x GROUP BY x.id 후 x.title x.id는 원래 기본 키 에러. 서브쿼리 결과에는 기본 키 제약이 없다

외래 키 쪽을 자세히 보기

두 번째 경우가 가장 헷갈린다. 회차 하나는 공연 하나에 속하니 공연 제목도 하나로 정해질 것 같다.

SELECT p.id, s.title
FROM performances p
JOIN shows s ON s.id = p.show_id
GROUP BY p.id;
-- ERROR: column "s.title" must appear in the GROUP BY clause ...

s.title은 shows의 컬럼이고, GROUP BY에는 performances의 기본 키만 있다. PostgreSQL은 테이블마다 따로 따지고, 외래 키를 따라가 추론하지 않는다. 해결 방법은 세 가지다.

  1. 그 테이블의 기본 키도 GROUP BY에 넣는다 GROUP BY p.id, s.id. 이제 shows의 모든 컬럼을 쓸 수 있다. 묶음은 더 쪼개지지 않는다(회차 하나에 공연이 하나라서). 가장 흔히 쓰는 방법이다.
  2. 쓰려는 컬럼을 GROUP BY에 넣는다 GROUP BY p.id, s.title. 컬럼이 하나둘이면 간단하다.
  3. 집계로 감싼다 min(s.title) 또는 PostgreSQL 16부터 있는 any_value(s.title). "어차피 하나니까 아무거나 달라"는 뜻이다. 의도를 읽기 어려워서 앞의 두 방법을 먼저 고려한다.
선택 읽기: 왜 PostgreSQL은 더 똑똑하게 추론하지 않나

쿼리가 맞는지 틀린지는 데이터가 아니라 스키마와 쿼리 모양만으로 정해져야 한다. 그래야 데이터가 바뀌어도 어제 되던 쿼리가 오늘 에러가 나지 않는다. 기본 키는 "이 테이블에서 같은 값이 두 번 나오지 않는다"는 가장 확실한 약속이라 판단 근거로 쓰기 좋다.

UNIQUE 제약은 NULL을 여러 번 허용할 수 있고, 외래 키나 JOIN 조건을 따라가는 추론은 쿼리 모양에 따라 복잡해진다. PostgreSQL은 판단을 단순하고 예측 가능하게 두는 쪽을 골랐다. 대신 기본 키 제약을 지우면 이 규칙에 기댄 쿼리가 깨진다. 그래서 그런 쿼리로 만든 뷰가 있으면 PostgreSQL은 기본 키 제약 삭제를 거절한다(view ... depends on constraint ..._pkey).

이 저장소 코드 읽기

같은 컬럼이라도 무엇으로 묶었느냐에 따라 종류가 달라진다. 이 저장소의 두 쿼리가 좋은 비교다. 쿼리를 읽을 때는 먼저 "무엇으로 묶었나, 한 묶음에 무엇이 몇 줄 들어가나"부터 확인한다.

회차 목록: 회차로 묶음

apps/api/src/shows/shows.service.ts의 공연 상세 회차 쿼리는 .groupBy(performances.id)로 묶는다. 한 묶음은 회차 하나와 그 좌석들이다(케이스 7과 같은 모양).

값 종류 이유
performances.id 그룹 GROUP BY 컬럼
performances.startsAt 그룹 함수 종속성
remainingSeats, totalSeats 그룹 count(performanceSeats.id) 집계
salesStatus 그룹 case의 입력이 isCancelled, startsAt, salesOpenAt(함수 종속성)과 remainingSeats(집계)뿐이다
isAlmostSoldOut 그룹 위 그룹 단위 값들로 만든 조건식

공연 판매 상태: 공연으로 묶음

apps/api/src/shows/show-sales-status.ts의 showSalesStatusSubquery는 .groupBy(performances.showId)로 묶는다. 한 묶음은 공연 하나와 그 회차들이다. 이번에는 performances의 기본 키로 묶지 않았으니, 회차 컬럼은 모두 행 단위다.

값 종류 이유
performancePriority의 case 행 입력인 startsAt, salesOpenAt이 회차마다 다르다
min(${priority}) (showPriority) 그룹 행 단위 순번을 집계로 줄였다
case ${showPriority} when 0 then 'on_sale' ... 그룹 그룹 단위 값으로 만든 case
min(salesOpenAt) filter (where ${priority} = 1) 그룹 집계. filter 안의 priority는 행 단위라도 된다

회차 목록 쿼리에서 그룹 단위였던 startsAt이 여기서는 행 단위다. 그래서 회차 상태를 정하는 case를 그대로 쓰지 못하고, 순번으로 바꾼 뒤 min으로 감쌌다. 자세한 흐름은 06 판매 상태 쿼리 읽기에 있다.

확인 문제

1. 아래 값 중 SELECT에 바로 쓸 수 있는 것은?

FROM performances GROUP BY show_id 쿼리다. 예시 데이터의 performances를 쓴다.

  1. max(starts_at)
  2. starts_at <= now
  3. count(*) filter (where is_cancelled)
  4. case when count(*) = 1 then '단일 회차' end
  5. show_id + 100
답 보기
  1. 된다. 집계라서 그룹 단위다.
  2. 안 된다. starts_at이 행 단위다. bool_or(starts_at <= now)처럼 집계로 감싼다.
  3. 된다. 집계이고, filter 안은 행 단위여도 된다.
  4. 된다. 그룹 단위 값(count(*))으로 만든 case다.
  5. 된다. 묶은 기준(show_id)과 상수로 만든 식이다.

2. 이 쿼리는 실행될까? 안 된다면 어떻게 고칠까?

회차 목록에 공연 제목을 붙이려고 한다. 함수 종속성으로 인정하지 않는 경우를 묻는다.

SELECT p.id, p.starts_at, s.title, count(ps.id)
FROM performances p
JOIN shows s ON s.id = p.show_id
JOIN performance_seats ps ON ps.performance_id = p.id
GROUP BY p.id;
답 보기

s.title에서 에러가 난다. p.starts_at은 performances의 기본 키로 묶었으니 되지만, s.title은 shows의 컬럼이라 함수 종속성이 적용되지 않는다. 외래 키를 따라 추론하지 않는다.

GROUP BY p.id, s.id로 고친다. 회차 하나에 공연은 하나라 묶음이 더 쪼개지지 않고, 이제 shows의 모든 컬럼을 쓸 수 있다.

3. 결과는 무엇일까?

예시 데이터로 JOIN이 행을 불린다를 묻는다.

SELECT p.show_id, count(*) FILTER (WHERE p.is_cancelled)
FROM performances p
JOIN performance_seats ps ON ps.performance_id = p.id
GROUP BY p.show_id;
답 보기

공연 1은 2, 공연 2는 0이다. 취소된 회차는 12 하나지만, 좌석 JOIN으로 회차 12의 행이 좌석 수(2개)만큼 불어났기 때문이다. 취소된 회차 수를 세려면 count(distinct p.id) filter (where p.is_cancelled)를 쓰거나 좌석 JOIN 없이 센다.

4. 이 diff 뒤에도 쿼리가 실행될까?

케이스 7의 쿼리에서 묶는 기준을 바꾼다.

 SELECT p.id, p.starts_at, count(ps.id)
 FROM performances p
 JOIN performance_seats ps ON ps.performance_id = p.id
-GROUP BY p.id;
+GROUP BY ps.performance_id;
답 보기

안 된다. JOIN 조건 때문에 ps.performance_id와 p.id는 값이 같지만, PostgreSQL은 performances의 기본 키로 묶었는지만 본다. p.id와 p.starts_at이 모두 에러다.
