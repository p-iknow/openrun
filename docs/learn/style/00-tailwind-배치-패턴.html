00 Tailwind 배치 패턴

클래스 하나로는 안 되고 몇 개가 함께 있어야 의도대로 배치되는 조합을 패턴별로 모은다. 패턴마다 푸는 문제, 클래스가 만드는 CSS, 이 저장소의 사례, 하나를 빼면 생기는 일을 적는다. 처음 패턴들은 공연 카드의 포스터 틀 (apps/store/apps-src/_index/index-page.sub/show-card.tsx의 ShowCardFrame)에서 나왔다.

한눈에 보기

<li className="flex gap-md sm:flex-col sm:gap-sm">
  <div className="relative aspect-3/4 w-[96px] shrink-0 overflow-hidden rounded-card bg-surface-muted sm:w-full">
    <Image src={card.posterUrl} alt="" fill sizes={POSTER_SIZES} className="object-cover" />
  </div>
  <div className="flex min-w-0 flex-1 flex-col gap-xs">{children}</div>
</li>
클래스 하는 일 패턴
aspect-3/4 w-[96px] 이미지가 오기 전에 포스터 자리의 크기를 정한다 비율로 자리 먼저 잡기
bg-surface-muted 이미지가 오기 전에 보이는 자리 표시자 비율로 자리 먼저 잡기
relative fill 이미지가 이 틀을 꽉 채우게 한다 fill 이미지의 기준 상자
overflow-hidden rounded-card 이미지 모서리까지 둥글게 자른다 둥근 모서리로 자식 자르기
shrink-0, min-w-0 flex-1 모바일 가로 줄에서 포스터는 96px로 두고 글자 칸만 줄인다 flex 줄의 고정 폭
sm:flex-col, sm:w-full 모바일은 가로 행, sm부터 세로 카드 화면 폭으로 방향 바꾸기

aspect: 비율로 자리 먼저 잡기

.aspect-3\/4 { aspect-ratio: 3 / 4; }
.w-\[96px\]  { width: 96px; }   /* 폭이 정해지면 높이는 비율로 128px이 된다 */

이미지는 내려받기 전까지 크기를 모른다. 크기를 모르는 <img>는 처음에 높이 0으로 그려졌다가 이미지가 오면 커지고, 그 아래 내용이 한꺼번에 밀린다. 이 흔들림을 CLS(Cumulative Layout Shift)라고 부른다.

  1. 틀이 크기를 정한다 폭과 aspect-ratio만 있으면 브라우저가 높이를 계산한다. 틀의 크기가 이미지와 상관없이 정해져서 이미지가 늦게 와도 아무것도 밀리지 않는다.
  2. 배경색이 자리 표시자가 된다 이미지가 오기 전에는 틀의 bg-surface-muted가 보인다. 정적인 색이라 서버 컴포넌트로 그릴 수 있다.
  3. 로딩 카드도 같은 틀을 쓴다 ShowCardSkeleton도 같은 ShowCardFrame에 Skeleton을 넣는다. 응답이 와서 로딩 카드가 진짜 카드로 바뀔 때도 자리가 그대로다.

aspect-ratio는 높이가 정해지지 않았을 때만 쓰인다. 같은 요소에 h-*를 함께 주면 비율은 무시된다.

relative: fill 이미지의 기준 상자

next/image의 fill은 크기를 모르는 이미지를 부모 크기에 맞춘다. 그려지는 <img>에는 아래 스타일이 붙는다. 

img { position: absolute; inset: 0; width: 100%; height: 100%; }

absolute 요소는 position이 static이 아닌 가장 가까운 조상을 기준으로 놓인다(자세한 동작은 style 01 문서). 그래서 틀에 relative를 붙여 기준을 틀로 만든다.

  • 빼면: 이미지가 카드 바깥의 다른 조상을 기준으로 커진다. 그런 조상이 없으면 첫 화면 크기의 상자를 기준으로 화면을 덮는다. Next도 개발 중에 부모의 position이 없다고 콘솔에 경고한다.
  • 함께 쓰는 것: 틀이 크기를 가져야 한다(aspect 패턴). absolute 이미지는 틀의 크기를 키우지 않으므로, 틀에 크기가 없으면 높이 0인 상자를 채운다.
  • object-cover: 이미지 비율이 틀과 다르면 비율을 지킨 채 틀을 꽉 채우고 넘치는 부분을 자른다. 지금 포스터는 틀과 같은 3:4라 잘리는 부분이 없다.

overflow-hidden: 둥근 모서리로 자식 자르기

.rounded-card    { border-radius: var(--radius-card); }
.overflow-hidden { overflow: hidden; }   /* 둥근 모서리 밖으로 나간 자식을 자른다 */

border-radius는 그 요소의 배경과 테두리만 둥글게 한다. 자식은 자기 모서리대로 그려지므로, 틀을 꽉 채운 이미지의 직각 모서리가 틀의 둥근 모서리 위에 그대로 보인다. overflow: hidden을 주면 자식이 틀의 둥근 모양 안쪽만 보인다.

  • 모서리는 틀 한 곳에서만 정한다: 로딩 카드의 Skeleton은 기본으로 둥근 모서리를 갖지만 rounded-none으로 지운다. 모서리는 틀이 자르므로, 틀의 반지름을 바꿀 때 한 곳만 고치면 된다.
  • 주의: overflow-hidden은 틀 밖으로 나가야 하는 것(툴팁, 포커스 링, 그림자가 있는 자식)도 자른다. 이런 것이 들어갈 틀이면 자식에 같은 rounded-*를 주는 쪽을 고른다.

shrink-0과 min-w-0: flex 줄의 고정 폭

.shrink-0 { flex-shrink: 0; }      /* 줄이 좁아도 줄어들지 않는다 */
.flex-1   { flex: 1; }             /* = 1 1 0%: 남는 폭을 가져가고, 시작 폭은 0 */
.min-w-0  { min-width: 0; }        /* 내용보다 좁아질 수 있게 한다 */

모바일 카드는 포스터와 글자 칸이 한 줄에 놓이는 flex 행이다. 포스터는 96px로 고정하고, 남는 폭을 글자 칸이 가져가며, 좁아질 때도 글자 칸만 줄게 하려고 세 클래스를 함께 쓴다.

  1. flex 항목은 기본으로 줄어든다 flex-shrink의 기본값은 1이다. 줄이 모자라면 w-[96px]를 준 포스터도 96px보다 좁아질 수 있고, aspect-ratio 때문에 높이도 같이 준다. shrink-0이 이걸 막는다.
  2. 글자 칸은 남는 폭을 가져간다 flex-1은 시작 폭을 0으로 두고 남는 폭을 모두 가져간다.
  3. min-width: auto가 줄어들기를 막는다 flex 항목의 min-width 기본값은 auto, 즉 내용의 최소 폭이다. 줄바꿈이 안 되는 긴 글자 (truncate를 쓴 공연장 이름)가 있으면 글자 칸이 그보다 좁아지지 않아 줄 밖으로 넘친다. min-w-0을 주어야 글자 칸이 줄고 truncate의 말줄임표가 나타난다.

지금 구조에서는 글자 칸이 min-w-0이라 먼저 줄어들어서, 화면이 96px보다 좁지 않으면 shrink-0이 없어도 차이가 거의 없다. 내용이 바뀌어도 포스터 폭을 보장하려는 방어용이다. 반대로 min-w-0은 빼면 긴 공연장 이름에서 바로 넘친다.

sm:flex-col: 화면 폭으로 방향 바꾸기

.flex       { display: flex; }                 /* 기본: 가로 행 */
@media (width >= 40rem) {
  .sm\:flex-col { flex-direction: column; }    /* sm부터: 포스터 위, 글자 아래 */
  .sm\:w-full   { width: 100%; }               /* 포스터가 카드 폭을 채운다 */
}

Tailwind는 모바일 먼저다. 접두어 없는 클래스가 가장 좁은 화면의 모습이고, sm:은 그 폭 이상에서 덮어쓴다. 한 마크업으로 모바일의 가로 행 목록과 데스크톱의 포스터 카드 그리드를 만든다. JS로 화면 폭을 읽지 않으므로 서버 렌더링 결과와 첫 화면이 같다.

  • 세로가 되면 shrink-0은 의미가 없다: flex-shrink는 주축(세로 배치에서는 높이)에 적용된다. sm부터 포스터 폭은 sm:w-full이 정한다.
  • 이미지 sizes를 열 수와 맞춘다: 이미지 폭은 CSS가 정하지만, 브라우저는 CSS를 읽기 전에 어떤 크기의 파일을 받을지 골라야 한다. sizes에 화면 폭별 표시 폭(모바일 96px, sm 3열 약 33vw, lg 4열 약 280px)을 적어 두어야 모바일에서 큰 파일을 받지 않는다. 그리드 열 수를 바꾸면 POSTER_SIZES도 함께 바꾼다.

스스로 확인하기

1. 포스터 틀에서 relative를 빼면 데스크톱 화면에서 무엇이 보이나?

fill 이미지의 기준 상자. 바꾸는 코드:

-<div className="relative aspect-3/4 w-[96px] shrink-0 overflow-hidden rounded-card ...">
+<div className="aspect-3/4 w-[96px] shrink-0 overflow-hidden rounded-card ...">
답 보기

이미지가 틀이 아니라 position이 있는 바깥 조상, 없으면 첫 화면 크기의 상자를 기준으로 커진다. 카드마다 포스터가 같은 자리에 겹쳐 화면을 덮는다. 틀은 크기를 그대로 가지므로 빈 회색 틀만 남는다.

2. 글자 칸에서 min-w-0을 빼면 360px 화면에서 무엇이 달라지나?

flex 줄의 고정 폭. 공연장 이름이 화면 폭보다 길고, 공연장 줄은 truncate다. 

-<div className="flex min-w-0 flex-1 flex-col gap-xs">
+<div className="flex flex-1 flex-col gap-xs">
답 보기

글자 칸의 최소 폭이 공연장 이름 전체 길이가 되어 줄 밖으로 넘친다. 말줄임표가 나타나지 않고 가로 스크롤이 생긴다. 포스터는 shrink-0이라 그대로 96px이다.

3. Skeleton에서 rounded-none을 빼도 화면이 같아 보이는 이유는?

틀이 overflow-hidden으로 자식을 자기 둥근 모서리 안쪽만 보이게 자르기 때문이다. 다만 Skeleton의 반지름이 틀보다 크면 모서리 안쪽에 틈이 보인다. 모서리를 한 곳에서 정하려고 지운다.
