# 어드민을 SPA로 만든다

스토어는 Next.js로 만들지만, 어드민은 Vite와 TanStack Router 기반 SPA로 만든다. 어드민은 모든 화면이 로그인 뒤에 있어 SEO가 필요 없고 서버 렌더링의 이점도 작은 반면, 넣으면 운영할 서버와 복잡도만 늘어나기 때문이다.

## 근거

- **서버 렌더링 이점이 작다:** 로그인한 사용자별 화면이라 공개 캐시를 쓰기 어렵고, 공유 미리보기도 필요 없다.
- **사용 패턴이 맞다:** 한 번 접속해 표와 폼을 오래 다루므로, 첫 로딩 비용을 이후 화면 전환에서 만회할 수 있다.
- **운영이 단순하다:** 정적 파일만 배포하므로 Node 서버와 장애 지점이 하나 줄어든다.
- **데이터 경로가 하나다:** 요청이 항상 브라우저에서 API로 가므로, 서버 렌더링 때 쿠키를 전달하는 경로가 필요 없고 권한 검증도 API에 모인다.
- **URL 상태를 다루기 좋다:** 필터, 정렬, 페이지 상태가 많은데, TanStack Router의 타입 안전한 검색 파라미터가 여기에 맞는다.

## 고려한 대안

- **Next.js 정적 내보내기:** 빌드 도구를 하나로 통일할 수 있지만, Next.js 기능 대부분을 쓰지 않으면서 그 규칙을 따르게 되고, 타입 안전한 검색 파라미터의 이점도 얻기 어렵다.

## 결과

- 프론트엔드 빌드와 배포 방식이 두 가지가 된다.
- 번들은 로그인 전에도 받을 수 있으므로 비밀 값을 넣지 않고, 권한은 항상 API에서 검사한다.
- 첫 로딩은 경로별 코드 분할로 줄인다.
- 탭을 오래 열어 두면 새 배포 후 예전 코드 조각을 못 불러올 수 있으므로, 이 오류가 나면 새로고침으로 복구한다.

## 재검토 조건

어드민에 공개 화면이 생기거나, 서버에서만 다뤄야 하는 처리가 화면 계층에 필요해지면 다시 검토한다.
