# 운영자 계정을 사용자 계정과 분리한다

운영자는 사용자 테이블의 역할 컬럼이 아니라 별도 `operators` 테이블에 두고, 세션과 쿠키도 따로 쓴다. 비밀번호 해시와 세션 발급·검증 로직은 함께 쓴다. 사용자와 운영자는 공유하는 동작이 없고(운영자에게는 가입, 주문, 리뷰, 찜이 없다) 권한 세분화도 없어서 역할 컬럼으로 얻는 것이 작다. 반면 분리하면 가입 경로나 역할 검사 누락으로 운영자 권한이 생길 길이 구조적으로 없어지고, 운영자에게만 짧은 유휴 만료를 걸 수 있다. 백오피스가 따로 있는 커머스 플랫폼(Magento, Shopify, Medusa, Spree)도 대부분 분리한다([조사](../research/customer-and-operator-accounts.md)).

## 결과

- 운영자 쿠키는 이름을 달리하고 Domain 없이 `api.도메인` 전용으로 굽는다. 어드민은 SPA라 서버 렌더링에서 쿠키를 읽을 일이 없다.
- API는 `/admin/*` 경로에서는 운영자 쿠키만, 나머지 경로에서는 사용자 쿠키만 읽는다.
- 스토어와 `admin.도메인`은 같은 사이트라 `SameSite`가 둘 사이의 요청을 막지 않으므로, 어드민 API의 CSRF 방어는 `Origin` 검사가 맡는다.
- 운영자 세션은 "로그인 상태 유지" 없이 30분 동안 요청이 없으면 만료된다.

## 재검토 조건

한 사람이 같은 계정으로 예매도 하고 운영도 해야 하는 요구가 생기면 다시 검토한다.
